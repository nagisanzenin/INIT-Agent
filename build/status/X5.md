## Public API (for X3-SENTINEL, X6, X7) — built against X3's `sentinel::{Turn, Hooks, req_caps}`

**Per request (egress → X3).** At the start of `Egress::finish` (every forwarded live request, errors included),
the egress calls `extend::request` → `crate::sentinel::req_caps(root, &req_id, &caps)` with
`caps: Vec<(String /*cap id*/, u32 /*uses*/, &'static str /*"root"|"zone"*/)>` (sorted; empty → no call):
- `root` evidence: the tool calls the model made, read by the tap (`egress/tap/calls.rs`) from the response bytes
  **after** each chunk is relayed, for `openai-chat`, `anthropic` and `openai-responses`, streamed or not:
  every call → `tool/<fn name>`; `ext` → `ext/<input.name>`; a `read`/`edit`/`write` `path` or a `bash` `command`
  holding `skills/<n>/` or `agents/<n>/` at a path-component boundary → `skill/<n>`, `agent/<n>`.
  Uses = calls (a call naming a cap twice counts once). Only these ids leave the tap; no argument text is kept.
- `zone` evidence: `x-egress-caps: <id>,<id>…` (each a valid cap id, else that id is dropped; more than 16 ids or
  more than 1 KiB → the header counts as absent), 1 use each. A cap seen with both evidences is reported once as `root`.
  The header never reaches the upstream (the egress forwards only its header allowlist; tests/x5.rs checks it).
- Pure helpers: `extend::{valid_id, valid_name, call_caps, zone_caps, request_caps}`.

**Hooks X5 registers** (`extend::start(root)`, from `egress::start`; it also publishes `caps.json` at start):
- `Hooks.caps = extend::change_caps` — `fn(&Root, &Value /*change.open args*/) -> Result<Value, Err3>` →
  `[{id, ver, prev_ver, op: "add"|"modify"|"remove", evidence}]`, sorted by id, diffed against the **current**
  tuple. `root` evidence computed from the store: `skill/<n>`, `agent/<n>` (see Deviations 5) and `prompt/GENESIS.md`,
  `prompt/SELF.md` (file sha256) from `candidate.body.t0` vs the parent's `body.t0`; `ext/<name>` (component sha256)
  from `candidate.ext.components` vs the parent's. Zone entries from `args.caps` are validated and kept for the other
  kinds (`tool`, `mod`, `mem`, `loop`, `kernel`, `dep`); a zone entry for a Root-computed kind is dropped.
  Err `root.args` (malformed entry, bad tar, over 8 MiB, more than 96 caps), `root.store` (t0 blob missing).
- `Hooks.turn_closed += extend::turn_closed` — `fn(&Root, &Turn)`: appends the usage line, folds the turn into its
  owner day, appends the `cap_use` records of finished owner days, republishes `caps.json`.

**Files.**
- `ROOT_HOME/extend/usage/<UTC date of turn end>.jsonl` (dirs 0700, file 0600, never mirrored; files older than 90 days
  removed by exact path). One ICJ line per closed turn:
  `{"caps":[{"evidence","id","uses"}],"cost_musd","day","end","groups","harm":[…],"harmed","kind","req_bytes","requests","start","turn","v":1,"wall_ms"}`;
  `harm` ⊆ `correction`, `crash`, `kill`, `provider_error`, `capped`, `refusal`; `day` = the owner day (local date).
- `INIT_HOME/root/caps.json` (0644, ICJ): `{"caps":[CapRow…],"day","v":1}`, at Root start and after every turn.

**Lineage.** `cap_use{day, part, caps:[{id, turns, uses, harm_turns, last_turn_seq, evidence}]}` per owner day with
turns (≤ 256 caps, the most recently used, sorted by id), split into parts under the lineage's 16 KiB, appended at
the first turn of a later owner day. After a restart the usage files of undigested days are read back first, so a
missed day is caught up and a digested day is never counted twice. A digest the lineage refuses is retried.

**The cap table** (`root.extend.table() -> Vec<CapRow>`, X6; X7's `ledger --verify` can recompute it with
`Extend::default()` + `apply` over the records + `table()`): a fold over Root-written `change_open`, `change_close`,
`cap_state` and `cap_use`, plus the undigested days.
`CapRow { id, ver, prev_ver, state, evidence, registered, group, turns, uses, harm_turns, last_turn_seq, last_day }`.
`state`: `active` on add/modify; `removed` on a `remove` op; `cap_state.to` verbatim; `observed` for a cap only ever
seen in use (seed components and trials: never decays). A `rolled_back`/`collateral` close restores each cap to its
row before the group (an `add` → `removed`), keeping the use counters. `registered` = introduced by a `change_open`.

**Lineage links (§5.3).** `egress_action` gains `caps` (≤ 16 ids used so far in its turn, `sentinel::turn_caps`, the
effect's own request included) and `open_groups` (group seqs, `sentinel::open_groups`).

## Deviations
1. The tap's call reader is `egress/tap/calls.rs`, a submodule of the existing usage tap (`egress/tap.rs` existed);
   the tap gets `with_calls()` (live forwarder only; sealed lanes never read calls) and `finish_calls()`.
2. The 4 KiB bound (§5.2) applies to the one captured value, not to the whole argument text: the scanner streams the
   arguments and holds only the wanted top-level string, so a `write` whose `path` follows 4 KiB of `content` is still
   attributed, and fewer bytes are held. A value over 4 KiB is read as its prefix (a long `bash` command).
3. `cap_use` gains `part` and is split so each record's data stays under the lineage's 16 KiB (256 caps ≈ 28 KiB).
4. `prompt/GENESIS.md` and `prompt/SELF.md` are exempt from the lowercase name grammar (the ADR's own ids break it).
5. Directory version, defined: sha256 over the directory's files sorted by path inside it, each `path NUL len(u64 BE)
   content`; tar metadata does not enter it.
6. `tool/<fn>` is counted for every call, seed tools included; caps never introduced by a `change_open` show state
   `observed` (never decay), because no genesis `core` list exists yet.
7. Usage files are named by the UTC date of the turn end (as the egress ledger); each line carries the owner `day`.
8. The egress now feeds the tap after relaying each chunk (it fed it before); the usage tap sees the same bytes.
9. A change naming more than 96 caps is refused `root.args`, so its `change_open` fits the lineage's 16 KiB.
10. A request that ends after its turn closed (the 15-minute cap) lands in X3's `turns()` copy but not in the usage
    line already written (X3's caveat); rare, and the next turn's line is unaffected.
