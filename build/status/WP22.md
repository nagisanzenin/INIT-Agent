# WP22: Root egress gateway (R2 and minimal R3)

Status: **done** for the Slice-1 path (2026-10-20, about 03:15 +07). Lane R. Spec: root/egress.md v0.2, plus root/root.md where the two meet (§3.10.5, §3.12, §3.13.1, §4.5).

## Done
- **`egress.sock`** (`egress.rs`, `egress/http.rs`): `ROOT_HOME/run/egress.sock` (0600), bound after cold start in `init-root start`, unless the Root is `Halted`. Same-uid peers only. HTTP/1.1 is parsed with `httparse`, bodies come by `content-length` or chunked (32 MiB cap), keep-alive is supported, and at most 64 requests are in flight (`root.busy`). Std threads only: one accept thread, one thread per connection, and a 60 s publisher thread.
- **Routes:** `POST|GET /<provider_id>/<path>` (model classes), `GET|HEAD /x/<class_id>/<host>/<path>` (http classes), and `GET /_root/ceilings` and `/_root/health` answered locally. `/_root/action` returns 501 `root.unsupported`.
- **Metering forwarder:**
  - One `ureq` 3.4.2 agent (rustls/ring, keep-alive pool, no redirects, `http_status_as_error(false)`).
  - Only the §4.1 kernel headers are forwarded. Any zone-sent `authorization`, `x-api-key`, cookie, `x-init-*` or `x-egress-*` header is dropped.
  - The Root adds `user-agent: init-root/<v>`, `accept-encoding: identity`, and the key: Bearer, or `x-api-key` for Anthropic and for DeepSeek's `anthropic/…` routes. The key is marked as a sensitive header and the temporary copy is zeroed.
  - Response bytes are relayed unchanged, chunk-framed. The response headers are the proxy.md §4.1 allowlist plus `x-egress-req-id`, `-retries`, `-reserved-musd` and `-epoch`.
  - Connect-phase failures are retried twice (250/500/1000 ms backoff). A status code is never retried.
  - 401/403 bodies are withheld and replaced by `upstream.auth` (alert `upstream_auth`). A 3xx becomes 502 `upstream.redirect`.
- **Keys:**
  - Keys come from `keys/providers/<id>`, read with R-F4 (`util::read_secret`): 1–512 bytes of UTF-8 with no control characters.
  - A key is held as `Secret` (no Debug or Display, zeroed on drop). It is never logged or returned. `keys.reload` and `egress stats` report states only.
  - A missing or insecure key means `class.disabled`, which is not a hit. An insecure key raises the alert `key_file_insecure`.
- **Money** (`egress/money.rs`):
  - Integer µUSD throughout. Day and total ceilings come from the charter, with the zone's total being `total − sealed.reserve_usd`. The owner day follows the charter's UTC offset.
  - Reservation: `ceil(bytes/3)×in + max_out×out`, the sum rounded up. `max_out` is `max_tokens`, `max_completion_tokens`, `max_output_tokens`, or the model's `reserve_output_tokens`.
  - Admission takes one mutex. Settlement uses peak prices, with cache reads charged at the input price.
  - Epochs keep a 1,024-entry ring for the D6 guard rules 1–3.
  - Class day volume (requests and bytes) and an exact integer token bucket per class; the rate limiter uses the Root clock, so the fake clock works.
- **Usage tap** (`egress/tap.rs`): `openai-chat` (DeepSeek hit/miss or OpenAI `prompt_tokens`), `anthropic` (cumulative fields overwritten, never summed) and `openai-responses`, over SSE or one JSON body. It parses only `data:` lines that contain a needle. Lines are capped at 1 MiB and a whole JSON body at 16 MiB. Finish classes are `tool_use`, `stop`, `length`, `error` and `other`.
  - A 2xx stream without usage (a cut, a parse miss or a panic) is charged its full reservation, flagged `usage_estimated` (RT-C7).
- **Usage ledger:** `egress/usage/<UTC date>.jsonl` (0600).
  - Records: `start` (fsynced before upstream), `end` (in the same file as its start) and `refuse`. They hold no content, URLs or keys.
  - Fail-closed: if `start` cannot be written, the request gets 503 `root.ledger`, an alert, and its reservation released.
  - Rebuild at start: a `start` without an `end` is charged its reservation. A `totals.json` checkpoint covers files more than two days old and is refreshed hourly.
- **Refusal format** (§3.6): 403/429/5xx with `x-init-egress-error` and `retry-after` (only `ceiling.day`, `class.volume`, `class.rate`). The body follows the wire family (Anthropic `{"type":"error",…}`, otherwise OpenAI-style) and carries a top-level ICJ `init` object: money figures plus `epoch` for ceilings, `retryable`, `demotes`, `level`, `class`.
- **D6 and lineage** (through WP20's `Root::append`, the R4 append):
  - `ceiling_hit{ceiling, code, limit, attempted, demotes, rule, source:"egress", class, level}` is written for every demoting refusal, and at most once per ceiling or class per owner day for ordinary ones.
    - Rule a: `class.destination|method|path|unknown|provider_tool`, and volume/rate on effectful classes.
    - Rule b: `class.level|model`.
    - Rule c: a money refusal that bypassed the guard.
  - `egress_action` is written for effectful (non-GET/HEAD) http classes.
  - The lineage holds no paths, queries or keys.
- **The guard epoch test (D6):** `x-egress-guard: epoch=<E>` is taken from a `;`-separated list. A refusal demotes if the header is missing or malformed, if `E` has left the ring, if `E+1` settled more than 30 s ago, or if at `E` the reservation already did not fit.
- **Classes** (`egress/classes.rs`):
  - The built-in `providers` (DeepSeek preset) and `crates` (D10, read-only; `static.crates.io` only under `crates/`).
  - The `providers` table schema is `{host, base_path?, auth?}`. Without it, the DeepSeek, Anthropic and OpenAI presets are derived from the destinations (kernel/proxy.md §3.5 base URLs).
  - Matching order: route → class → destination → method → path → class level → model listed/level → provider tools (`tools[].type`, `mcp_servers`, `background:true`) → availability (enabled, safe mode, test mode, key) → volume → rate → money.
  - `validate_actions` also checks providers, and loopback destinations only in test mode.
- **Levels:** `set_level` is called when the egress starts (from the folded ledger), after every `ladder` record (`Root::append` → `sync_egress`) and after `charter.apply`. Safe mode allows only `providers` and the L0 models.
- **`GET /_root/ceilings`** and `egress::ceilings()`: the §4.2 block (money, models with `routable`, class headroom). `INIT_HOME/root/ceilings.json` is written every 60 s and on reload, with `instances` and `parallel_bodies` limits whose `active` count stays 0 until WP21.
- **Wiring:**
  - `panic` → `egress.panic()` (503 `root.panicked`, kernel connections shut); `resume` → `egress.resume()`.
  - `charter.apply` → `egress.reload()` (a lowered ceiling refuses at the next admission and stops nothing; D6/RT-C10).
  - `keys.reload` → reload, returning the key states. New owner command `egress.stats` and CLI `init-root egress stats`.
  - Alerts now carry a `source` (`Root::alert_from`); egress alerts are deduplicated for 10 min.
- **Test-mode loopback upstreams:** with `root.test_mode = true`, `127.0.0.1:<port>`/`localhost:<port>` destinations are allowed (plain HTTP), and the egress never forwards to a non-loopback host (`class.disabled`). Production rejects loopback at C11.
- **`ci/local.sh`** (allowed for this WP): adds the step `root test (test-fixtures)` (`-p init-root --features test-fixtures`) with `INIT_MOCKLLM_BIN=$kernel_target/debug/init-mockllm` when that binary exists. The plain `root test` step is kept.

## Deviations
1. **Size.** egress.md §6 budgets 330 lines; the egress is 1,472 (see above). Nothing was cut from the specified Slice-1 feature set.
2. **Test-mode key marker.** Test mode loads only keys that start with `test-`. Any other key is `refused` and raises alert `key_file_real`. This is how "refuses real key files" (testing.md §3.4.1) is made mechanical.
3. **Loopback rules.** Loopback destinations are allowed in test mode only, including for `crates`. Test mode never forwards to a non-loopback host. `validate_actions` takes a `test_mode` argument.
4. **Money details the doc leaves open:**
   - The total is checked before the day, so the non-retryable reason surfaces first.
   - A cost counts toward the owner day it was admitted in.
   - A non-2xx upstream answer costs 0. A non-connect transport error is charged the reservation.
   - Cost is rounded up once over the sum.
   - `start` records are fsynced one by one, with no 5 ms group commit. `end` records are not fsynced on their own.
5. **Panic.** Kernel connections are shut at once. An in-flight upstream TCP connection closes at its next upstream frame (ureq has no cancel handle), not "within 100 ms". Its reservation is charged in full.
6. **D6 reading.** An unlisted model (`class.model`) demotes under rule b. Safe-mode refusals of other classes are `class.disabled` (not a hit).
7. **Lineage kinds.** There is no kind named `egress`. Egress writes the two Root kinds root.md §3.10.5 assigns to it: `ceiling_hit` (plus `class` and `level` fields) and `egress_action`. Refusals also get a `refuse` ledger line, so that ordinary hits are "counted in the ledger".
8. **Guard header.** I follow egress.md (`epoch=<E>`). kernel/proxy.md §3.8 still shows an older `day=…;total=…;seen=…;r=…` form. The parser reads the `epoch=` field from any `;`-separated list.
9. **`/_root/health`.** Its body (`{level, ok, panicked, test_mode, v}`) is defined here.
10. **Test upstream.** The tests drive `init-mockllm` as a binary, not through the `init-testkit` library. When this WP started, the library did not compile because WP3 was mid-edit and uncommitted. A dev-dependency on it would also make Root CI break whenever lane T is mid-edit. Header and fault tests use a small capturing upstream inside the test file. The fake kernel `init_testkit::link::Link`, which the coordinator relayed, is not used: WP22's kernel interface is HTTP on `egress.sock`, not the control link. It belongs in WP21's tests.
