## Deviations
1. **G1 stays inside A1** for t1/t2/dep: G2's head-prefix check reads G1's tools hash. **A2 keeps both G2 arms**
   (the parent arm gives the prefix to compare); ≈ $0.001 more than the ADR's candidate arm only.
2. **A1's clippy and body tests are still blocking** (G0 fails hard on them, as before); the ADR makes them advisory.
   Stricter, never weaker. K1's A3 re-reads G0's `test` step and vetoes only if a test failed with a pass (cannot
   happen while G0 blocks). Making them advisory needs a G0 mode in kernel-gate g0 (not in X2's file list).
3. The kernel mirrors the Root's `lkg` locally only when the closed group's head is the running version and no older
   group is open; an intermediate close leaves the local LKG for the next close (the Root's pointer stays authoritative).
4. `extend.rollback` to a target other than the kernel's LKG (rolling back the newest of several open groups) is not
   done kernel-side: the kernel alerts and the Root's 120 s whole-system rollback acts. Kernel-side intermediate
   targets need `store.get` of the parent's binary/ext/t0.
5. `Cap:` op: `remove` on a `retire` commit, `modify` when the parent's `self.json` names the id, else `add`; versions
   are left to the Root (it computes skill/agent/prompt/ext; zone kinds carry none).
6. Gate record versions: gated stays `v:2` (RECORD_V); the free path writes `v:5` (`RECORD_V_FREE`).
7. seed `skills/evolve/SKILL.md` (listed in X1's row) is left to X11, which owns the skills text (`skills/extend`), so
   the seed's `self.json` changes once.
