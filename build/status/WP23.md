# WP23: R4 lineage (hash chain, `idem`, verification, view, mirror, `lineage/kernel.git`)

Status: **done** (2026-10-20). Lane X, in the same crate as WP21 (lane R). Spec: root/root.md §3.10, §3.11, §3.8.1, §4.1.3, §4.7, §8; v03-decisions D7 and D13.
Owned paths: `root/crates/init-root/src/lineage/**` and `tests/wp23.rs`. The old `lineage.rs` is now the `lineage/` module. Every wiring line in WP21's files was made by WP21 (528c051).

## Done
- **Record format and appending** (`lineage/mod.rs`). This keeps the WP20 API that WP21 uses (`Lineage::open`, `append(by, kind, data)`, `append_at`, `.head`, `records`, `ensure_key`).
  - ICJ records with domain-separated Ed25519 signatures (`ed25519-dalek` 3.0.0).
  - Each record is one `write_all` to a file opened with `O_APPEND`, then `sync_data` (`F_FULLFSYNC` on Apple). Then the view copy, then `head.json` (`verified_full_at` is preserved).
  - `Head` gains `prev`.
- **Torn tail at open.** An unterminated final line is copied to `lineage/torn-<ms>.bin`, and the file is truncated to the last complete line. This is the only rewrite.
- **Checks at open** (§3.6.5 step 3):
  - rules 1–4 and 6 on every line, and signatures (rule 5) on genesis and the last 1,000 records;
  - rule 7 on `head.json`. A head one record behind (a crash after the line) is rewritten. A head ahead of the chain (truncation) is an error, which means `Halted{lineage}`.
- **Root-written kinds** (§3.10.5) are checked against an allowlist. It includes `ceiling_hit`, `egress_action`, `family_eval`, `audit` and `mutation`.
  - Demoting `ceiling_hit` records are capped at `kernel_lineage_per_hour` per hour (WP22's request; see deviation 4).
  - After `panic`, `ladder`, `rollback`, `kernel_upgrade`, `audit`, `charter`, `halt` and `crash_loop`, the mirror thread is woken at once.
- **Kernel records** (D7, `Lineage::append_kernel`, Root wrapper `lineage::kernel_append(root, build12, args, &relayed)` for the control link):
  - The `idem` key must be 1–64 printable bytes. It is indexed in `lineage/idem.jsonl` **before** the record is written. A duplicate returns the original `{seq, hash}` with `dup:true`.
  - At open the index keeps only the keys of the last 7 days whose record is in the chain with the same hash. A key whose record never landed is dropped and compacted out.
  - `by:"kernel:<12 hex>"`. Rate limit: `kernel_lineage_per_hour` gives `root.rate`, and alert `lineage_rate` at most once an hour.
- **Kind registry** (`lineage/kinds.rs`):
  - Every kind the docs use for kernel records: root.md §3.10.5, plus supervise.md §4.7 (`handoff`, `fetch`, `kernel_start`, `owner_signal`, `halted`, `level_applied`, `fleet_member`, …), gate.md (`admission`, `import`), evolution.md §4.4 (`validated`, `prediction`, `usage`, `retire_list`, `thinning`, `upstream`, `fleet`) and initctl.md (`vendor`, `kernel_proposal`). That includes `task_suspended` and `fleet_campaign`, plus `x_[a-z0-9_]{1,40}`.
  - Generic checks: ICJ (no floats), at most 16 KiB, depth at most 8.
  - Required fields for the kinds the Root interprets, plus type checks on `lkg`, `on`, `audit_required` and `components`.
  - The `owner` record: `qid` must name a line the Root relayed, and the line's first word must be that signal (RR-18c).
  - Privacy (§3.10.6): no string or key may contain the owner's home, ROOT_HOME or INIT_HOME, or an e-mail address other than `agent@init.local`.
- **Verification** (`lineage/verify.rs`):
  - `chain()`: rules 1–6, plus `key_rotate` support for rule 5. `check_head()`: rule 7. Rule 8 lives in `mirror::check_prefix`.
  - `audit_verify(p, full, view)` is the CLI's `init-root audit verify [--full] [--view]`. Without `--full`, signatures cover the last `root.lineage_verify_tail` records. `--view` checks `INIT_HOME/root/lineage.jsonl` under `INIT_HOME/root/lineage.pub`, as the agent can.
  - Exit codes: 0 valid; 1 prints `lineage INVALID at seq N: <rule>`.
- **Published view** (§3.10.6): `INIT_HOME/root/lineage.jsonl` stays a byte copy. Open rebuilds it if it differs. Append appends to it, or rebuilds it on a length mismatch, which also heals a race with another writer.
- **Mirror** (`lineage/mirror.rs`, §3.11):
  - **Off** unless `mirror.url` is set. With `root.test_mode`, only `file://` URLs are used and any other URL counts as off, so a test can never reach a network.
  - `$RG`: env cleared, `GIT_CONFIG_GLOBAL=/dev/null`, `TZ=UTC`, identity `init-root <root@init.invalid>`. SSH uses `-F /dev/null -i keys/mirror_ed25519 -o IdentitiesOnly=yes -o BatchMode=yes …`, with paths quoted. `protocol.allow=never` except ssh and file.
  - The repo is `lineage/mirror.git`. Its tree holds `HEAD.json`, `lineage-NNNNNN.jsonl` in chunks of 10,000 (full chunks are reused from the parent tree) and `lineage.pub`.
  - Each push: `commit-tree`, then CAS `update-ref`, then `push --porcelain` (never `--force`). `ls-remote` must show the commit. Then `gc --auto`.
  - Every git call is killed after 120 s, by its own handle.
  - The thread is `mirror::spawn(&root, halt)`:
    - pushes every `push_interval_s` when there are new records, and at once after the urgent kinds;
    - backs off from 60 s to 3,600 s, and alerts `mirror_failing` after 24 h;
    - on a non-fast-forward it alerts `mirror_diverged` and stops pushing;
    - runs the mirror-ref panic channel: `ls-remote <url> refs/heads/panic` every `panic.mirror_poll_s` calls `panic(root, "mirror_ref")` once per commit id;
    - runs the daily full verification. On failure it drops the lineage handle, alerts `lineage_corrupt`, and calls `halt`, which is WP21's `sup::integrity_halt` and enters `Halted{lineage}`.
  - `mirror::status()` supplies `status.mirror`: `{state: off|idle|ok|failing|diverged, pushed_seq, last_push_at, last_error}`.
- **`lineage/kernel.git`** (`lineage/kgit.rs`, §3.8.1, D7). `$RK` uses `transfer.fsckObjects=true`.
  - `import`: a bundle with exactly `refs/heads/release`, imported create-only as `refs/upstream/<v>`. The same commit again is a no-op; a different one is refused.
  - `import_release`: every `kernel/src/<v>.bundle`. With exactly one bundle it also creates `main`.
  - `update`: CAS. `None` means create-only.
  - `fetch_agent`: fetches the exact sha through the given upload-pack (WP21's `sandboxed-upload-pack`) from a repo under INIT_HOME into the create-only `refs/init/karchive/<sha>`. The commit must descend from `main`.
  - `rollback`: keeps `refs/init/rolled-back/<sha>` and moves `main` back by CAS.
- **Fault points** (`lineage/fault.rs`, test builds only): `INIT_FAULT=<point>[@n]:<abort|exitN|enospc|hang|sleepMS>`. Points: `root.lineage.mid_append` (half a line, then the action), `root.lineage.after_append`, `root.lineage.after_idem`, `root.mirror.after_commit`, `root.kgit.after_fetch`.

## Deviations
1. **"RT-L*"** in my brief maps to the Root's own lineage tests in root.md §8: RR-16…RR-19, plus 18b and 18c. testing.md calls them "RT-16…RT-19". The ladder rows RT-L1…L9 belong to WP25. `r4.verify` is `init-root audit verify --full` (and `--view`), and every WP23 test ends with it.
2. **`idem` order.** The key is indexed *before* the record (write-ahead), so a resend after a crash anywhere cannot duplicate. §4.7's `root.lineage.after_idem` therefore sits after the index line and before the record. The "rebuilt from the tail" wording is not needed, because `idem` stays out of the chain, as §3.10.3 requires.
3. **Fault points** are compiled under `test-fixtures`. There is no `fault-injection` feature, because Cargo.toml is WP21's. In-process unit tests use `enospc` where the binary test uses `abort`: the state on disk is the same.
4. **Demoting `ceiling_hit` cap:** at most `kernel_lineage_per_hour` an hour. Beyond that the record is not written (`root.rate`, logged); the egress usage ledger still has every refusal. The doc says "every". This follows WP22's flood concern, and one incident costs one level anyway.
5. **Root-kind allowlist:** `append(by:"root", …)` refuses kinds outside §3.10.5. Today every Root caller's kinds are on the list. `key_rotate` is reserved, so verification supports it but nothing writes it.
6. **Kernel kinds:** "required" means the key is present, and null is allowed, because the kernel sends `gate_job`, `scope` and `ext_set` as null on handoff promotions. `owner_signal` (supervise.md's name, no qid) is recorded without interpretation. Only `owner` gets the qid check.
7. **Tail check at open:** a constant 1,000 records, which is the charter default. `audit verify` reads `root.lineage_verify_tail`. Every line still gets the structural rules at open.
8. **Rule 7 tolerance:** a `head.json` one record behind is accepted by `audit verify` (an append in progress) and repaired at open.
9. **Mirror details:**
   - chunks go through `hash-object --stdin` rather than `lineage-chunk.tmp`;
   - urgent kinds bypass the backoff;
   - `mirror_failing` fires 24 h after the first failure following the last success;
   - `diverged` lasts until the Root restarts;
   - the mirror-ref channel fires once per commit id, so after `resume` a stale panic branch does not re-panic until it changes;
   - rule 8 fetches into `refs/mirror/remote`, and an unreachable mirror prints "not checked" (exit 0);
   - test `file://` URLs percent-encode spaces, because C9 refuses whitespace.
10. **Template mirror URL.** "OFF by default" holds for the code and for `mirror.url` (default `""`). But the D13 template (WP20) writes the GitHub URL, so a *production* install from the template has the mirror on, and its pushes fail harmlessly until the repo exists (M0), as §3.11 says.
11. **kernel.git:**
    - `import_release` creates `main` only when there is exactly one bundle;
    - `fetch_agent` fetches straight into `karchive` and checks ancestry afterwards, in the spec's order, so a refused non-descendant keeps its archive ref.
12. **The daily check halts through a hook** (`spawn(root, halt)`), because `Slot` is WP21's (it now has `retry_at`).
13. **Size:** 942 lines against root.md §4.8's 130 for `lineage.rs`. Nothing in the specified feature set was cut. The Root total budget needs a decision.
14. Tests honour `$WP23_HOMES`. I used it while the shared tree did not compile and I developed in a scratch export of HEAD.
