## Deviations
1. **Template homes instead of `init-kernel install --template`**, which is not built. Each test process builds `target/t15/tm-{seed,fake,fx}`. Each template holds:
   - the seed tree committed as X, as `lineage/body.git` plus the agent clone `body/` (origin `../lineage/body.git`);
   - `lineage/trees/<sha12>/`;
   - `bin/init-body{,.lkg}` and the seed `lkg.json` that install writes;
   - `kernel/config.toml` and `kernel/CONSTITUTION.md` (the Root's asset; the fake Root writes none);
   - wrappers for `kernel/bin/init-kernel` and `initctl`.

   A scenario copies its template with the runner's own `fixture.work` entry `".."`, which is applied after the body binary and before `kernel_config`.
2. **Homes go under `target/t15/`, not `target/test-homes/wp15/`.** A probe lane socket (`<home>/probe/<12 hex>/run/kernel.sock`) must fit in 103 bytes.
3. **`INIT_KERNEL_BIN` is a one-line `exec` wrapper.** `init-fakeroot` SHA-256es its `--kernel` file at start with the debug sha2, which takes about 10 s for the 154 MB debug kernel. That is past the runner's fixed 10 s `owner.sock` wait.
4. **A3/A4 use WP8b's model-driven fixture body**, a one-file crate that execs `sv-agentbody` (`fixtures/fx-body/`), not the seed. A G0 build of the real seed (wasmtime) per candidate does not fit tonight's disk budget.
   - Their mock is not `--strict deepseek`, because `sv-agentbody` does not echo DeepSeek's `reasoning_content`. The strict protocol is covered by A1, A2 and A6 with the real body.
   - Events are asserted in `sv-agentbody`'s log schema (`{type:"message", msg:{role, content}}`).
5. **A4's patch is "print the boot reason" plus the injected panic** (gated on `INIT_BOOT_ID`); the fix removes only the panic. The spec's change+fix pair would squash to an empty diff. The fix commit puts its explanation in the body, because a wrapped `Why:` line is `trailer.block_mixed`.
6. **A5-fake runs under the fake Root, as the orchestrator asked.** That covers the kernel half only: the fake Root never demotes. Its `start` after a stop stands in for the Root's normal-mode restart (safe auto-clear). The fake body has no model, so a test-side helper plays the agent's one tool call (`initctl promote evo/x`, as the body's bash would) and leaves the answer in `work/a5/promote.json` for the scenario's `wait_file`. The Root half (demotion, rollback to audited-good, system safe mode, auto-clear on the fake clock) is WP21's `crash_loop_safe_mode_halt_retry_and_self_clear` against the real `init-root`.
7. **A6 drives the real Root directly**, the same way `scripts/slice1/s1.sh mock` does (`root.test_mode`, temp homes, a test key, owner `HOME` for `start`), rather than through the runner's disposable-only `start_root`. This build has no sweep, and panic kills held processes only. Other A6 changes:
   - Step 3 uses `192.0.2.1` (TEST-NET-1) instead of `example.com`, so a broken sandbox still could not reach the internet.
   - Three extra refusals and three controls were added.
   - `state/kernel/` is not checksummed, because the kernel writes there. A probe file checks that the body cannot write it.
8. **The agent waits for its initctl server** (an `initctl ping` loop before `promote`/`reload`). The kernel binds `run/kernel.sock` anywhere from about 2 s to more than 60 s after the body is ready, and the runner's `wait_file` cannot wait for a socket because it `read`s the path.
9. **A2 build command:** cargo gets `--config source.vendored-sources.directory=<repo>/vendor`, because the seed's `.cargo/config.toml` names `../vendor` relative to `body/`, and a test home has no vendor tree. The A2 mock script is generated into `target/t15/gen/` from `scenarios/scripts/a2.mock.jsonl`, with the extension's files and the version lists taken from `fixtures/`, so there is one source of truth.
10. **First-turn mock expectations check `last_role:"user"` only.** The current body appends its boot `[init:reload] ext generation 1` report after the owner's message.
11. **NO-OWNER-1, static half:** every scenario file passes the runner's `validate()`, and no `send_user`, `root_cmd` or `root_request` carries `/accept`, `/bless`, `/reject`, `/approve`, `/deny` or `/clear-safe`. A6 is Rust-driven, not a scenario file; it sends one owner line of task text.
12. `fixtures/charters/phase0.toml` is WP3's charter, copied to the repo-root `fixtures/` (WP3 asked WP15 to own the charter fixtures).
