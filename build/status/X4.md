## Public API — `crate::snapshot` (root/crates/init-root/src/snapshot.rs)

`Err3` = `crate::zone::Err3` (code, message, data). Everything here runs at $0.

- **`snapshot::admit(root, args, first) -> Result<Value, Err3>`**, registered as `sentinel::Hooks.admit` by
  `snapshot::register()` in `main()`.
  - Reads `args.scope`, `args.candidate{body:{binary, sha, t0}, ext}`, `args.group` and `args.parent_tuple`. X3 injects
    the last two; `parent_tuple` falls back to `ptrs.current`.
  - For `t2` and `dep`, it runs A4: the candidate tuple against the group's parent tuple.
  - When `first` is true, it then takes the system snapshot.
  - Ok: `{"A4": "pass"|"skip", "snapshot": "<id>"|null}`.
- **`snapshot::take(root, group: Option<u64>) -> Result<Value, Err3>`**: the §4.2 system snapshot.
  - What it copies: `S_A` = `INIT_HOME/body/`, `state/` without `sessions/` and `spill/`, and `vault/` without `traces/`.
  - Where: `ROOT_HOME/snapshots/sys/<group>/` plus `<group>.json`.
  - Ok: `{"id","kind":"sys","group","logical_mib"}`, and it appends `snapshot{id, kind, group, logical_mib, skipped}`.
  - Refusal `extend.snapshot_too_large`: logical size over 16 GiB, not APFS, or another volume. It alerts
    `snapshot_too_large` and records `skipped:"too_large"`.
  - Refusal `root.quota`: free disk below the floor plus 2 GiB, or 16 snapshots pinned.
  - Refusal `root.internal`.
- **`snapshot::restore(root, id: &str, reason) -> Result<Value, Err3>`**: R2. It is also `sentinel::Hooks.restore`
  (that variant returns `Result<(), String>`).
  - It refuses with `root.busy` `{reason:"zone_live"}` while `root.zone.count(None) > 0`. The check runs before it starts
    and again before each tree.
  - It first clones the live `S_A` to `pre-restore-<n>`.
  - It never touches `state/sessions/`, `state/spill/` or `vault/traces/`, and never follows a link.
  - It appends `snapshot{kind:"pre_restore"}` and `restore{snapshot, reason, kept, saved}`.
  - It neither stops the zone nor starts the tuple. The caller does those: root.md §3.7.3 step 1 before, step 5 after.
- **`snapshot::a4(root, cand, parent) -> Result<Value, Err3>`**: the A4 rollback probe, run by the Root.
  - `cand` and `parent` are tuple objects.
  - It holds the sealed OP lock (`sealed::try_begin`); if a sealed operation is already running it answers `root.busy`
    `{reason:"sealed"}`.
  - It calls `snapshot::probe(env, cand, parent, wall)`.
  - Refusal `extend.rollback_incompatible` `{arm, exit, ready, why}`.
  - Refusal `root.store`: a missing blob or T0 source.
  - Refusal `root.args`: a bad candidate.
- **`snapshot::prune(root)`**: §4.2 retention. It keeps:
  - the snapshots of open groups (`change_open` without `change_close`);
  - the newest snapshot at or before the last `lkg`, `settled` and `twin` moves;
  - the newest `pre-restore`;
  - anything younger than 10 minutes.

  Everything else is removed by exact path. `take` and `restore` prune too.
- **`snapshot::settled_of(records, now_ms)`** is the pure fold. **`snapshot::settled_tick(root)`** appends `settled{tuple}`
  when the pointer moves.
- **`tuple::Ptrs.settled`**, folded from `settled` records.
  - `tuple::rollback(root, "settled", …)` targets it.
  - The fallback order is want → lkg → settled → audited → genesis.
- The lineage kinds `snapshot`, `restore` and `settled` were added by X3 (076544f).
- **Body mode `check`** (seed): `INIT_MODE=check` boots, rehydrates `INIT_SESSION`, appends its boot event, writes
  `state/run/ready` (`mode:"check"`) and exits 0.
  - It does no git sync and starts no extension host (`ext:{"status":"disabled"}`).
  - It writes no heartbeat and does not serve.
  - Its summarizer refuses, so it makes no model call and needs no kernel socket.
  - `--manifest` `modes` = `["normal","probe","safe","check"]`.

Records read (field names as ADR-011 §Records): `change_open{group, tuple, snapshot, caps[{id, ver, op}]}`,
`change_close{group, attribution}`, `cap_state{cap, ver, to}`, `lkg{tuple}`, `settled{tuple}`, `twin{tuple}`.

## Done

- **§4.2 system snapshot.**
  - Each tree is one `clonefile(2)` with `CLONE_NOFOLLOW`, so its path resolves once. If the zone swaps a tree for a
    link, the link is cloned, detected and refused. The excluded entries are then removed from the clone, inside
    ROOT_HOME.
  - Checks: logical size, APFS, same volume, and A5 room. Retention is described above.
  - **Measured:** a 64 MiB agent state costs **16 KiB** of free disk to snapshot (RF-15 prints it). The snapshot is an
    APFS clone, so it shares blocks with the live state.
- **R2 restore with the zone stopped.**
  - A pre-restore clone is taken first, so a restore can itself be undone; RF-15 tests that.
  - Entries are removed without following links, and the excluded trees are kept.
  - It stops if a zone process appears partway through.
- **Root-owned probe roots and A4.** The probe root is a sealed run root that holds:
  - an APFS clone of the live `state/` without `spill/`, `run/ready` or `run/heartbeat`;
  - the arm's T0 (its `t0` blob, else the kernel-exported tree `lineage/trees/<sha12>/`);
  - `bin/init-body` and `bin/ext/<name>.wasm` from the store;
  - `boot.json` with `mode:"check"`, the live session and the arm's sha.

  The candidate runs first, then the parent on the state the candidate left. Each must exit 0 and write `ready` with its
  own boot id and `mode:"check"` within 90 s. Both run under the sealed profile with no lane, so they cannot read the
  live `INIT_HOME` or ROOT_HOME (RF-16 checks this) and have no network. The memory watchdog and the disk floor of
  sealed runs apply. The root is removed by exact path.
- **Body mode `check`** in the seed.
- **The `settled` pointer:** the fold, the tick, `Ptrs`, and the rollback target.
- **What cannot be undone** is stated in the module docs of snapshot.rs (§4.4 limits, §4.6 list) and below.

## Deviations
1. **Probe roots are sealed run roots** (`ROOT_HOME/sealed/run/<id>/`, listed in `sealed/runs.json`), not
   `ROOT_HOME/probes/<seq>/`. This reuses the sealed runs' listing, stale clean-up at Root start, panic's `cancel_all`,
   the memory watchdog and the disk floor.
2. **Profile.** The probe uses PRELUDE + the sealed tail, which is exactly how sealed body runs are confined. It is
   spawned by `sandbox-exec` in its own process group, the same way. The ADR asks for "the `body` profile plus the sealed
   tail, through exec-clean"; the sealed profile is strictly narrower (no INIT_HOME, no ROOT_HOME outside the run root,
   no IP, no workspace). As a result `zone.rs` and `root/sandbox-profiles` are unchanged.
3. **One sealed-kind operation at a time.** A4 takes the sealed OP lock. While an audit, slice or gog runs, A4 answers
   `root.busy` and the kernel retries.
4. **Ids.** Snapshots are named `<group>` (as in the ADR), `t<ms>` when no group is given, and `pre-restore-<n>`, where n
   is a counter (the ADR says `<seq>`).
5. **Cloning.** A whole tree is cloned and the excluded entries are then removed, instead of cloning entry by entry.
   This makes the never-follow-a-link check atomic. The cost is a metadata-only clone of `sessions/`, `spill/` and
   `traces/`.
6. **`snap_max_gib`** is the constant 16 until X7's charter `[extend]` and grant overlay land (`snapshot::snap_max`).
7. **A5's "room for the system snapshot"** is implemented as: `root.quota` when free disk is below the floor plus
   2 GiB, or when 16 snapshots are pinned.
8. **`settled`:**
   - "lkg for ≥ 7 days" is read as "became lkg at least 7 days ago". Being superseded by a newer lkg does not disqualify
     a tuple.
   - "Its groups" are the groups whose `change_open` named that tuple.
   - A quarantine disqualifies a tuple when it names a cap version that one of those groups added or modified.
9. **Retention "at or before"** a pointer move is decided by time (`at_ms` ≤ the record's `at`). A snapshot younger than
   10 minutes is never pruned, because its `change_open` may not have been appended yet.
10. **Mode `check`** also skips the git sync (as probe does), loads no extension and writes no heartbeat. It "may
    migrate its state" only through boot and rehydration.
11. **Root size.** snapshot.rs has 483 non-comment lines, against the ADR's estimate of about 270 (snapshots ≈ 150,
    probe ≈ 120). The probe and the wrappers took the extra lines.

## What cannot be undone (ADR-011 §4.6, restated)
- **Money spent** with the provider. It is bounded by the ceilings, the background share and H5.
- **Data sent to the provider,** including the owner's files the agent read. H11 flags volume; the deny list and
  `read_deny` are the only prevention.
- **Executed external actions** (`git-push`, `email`, non-GET `http`), once the charter lists such a class.
- **Writes outside the workspace in full mode.** No home snapshot exists.
- **Deferred execution** that the owner later runs: workspace build files, scripts, editor configs.
- **The owner's own actions** on the agent's output.
- **Processes that escaped** with `setsid` before a poll.

Limits of what is reversible:
- A4 covers only state written at boot.
- R2 loses agent state written since the snapshot from the live tree; it is kept in `pre-restore-<n>`.
- Snapshots are crash-consistent, not transaction-consistent.
- No snapshot is taken above 16 GiB, off APFS, or on another volume. Linux needs reflink or btrfs (TODO).
- The conversation, spill and traces are never rolled back.
