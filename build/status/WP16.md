## Done
- **`init-measure`** (`kernel/crates/init-testkit/src/bin/init-measure.rs` plus `init-measure/{common,builds,rig,m4,m5}.rs`):
  - **`env`** prints testing.md §3.11's environment record: machine, toolchain, load, AC power and free disk.
  - **`m1` and `m2`** time `cargo` under `/usr/bin/time -l` with `CARGO_INCREMENTAL=0` and an existing `CARGO_TARGET_DIR`. Each run does a warm-up, then N no-ops, then N `touch` rebuilds. A run flags `Compiling` and lock waits. `m2 --stage-fixture` stages `fixtures/ext/<name>` as `body/ext/<name>` of a throwaway body tree.
  - **`gen-steps`** writes the M-5 mock script: N `printf` bash steps, a 5,000-line `read` every 100th step, the end turn, and compaction replies.
  - **`m4`** is a body-level overlapped handoff on the real `init-body` in socket mode, chained over N fresh processes, plus a negative control that edits `SELF.md`. It reports prefix identity and the timings of each phase.
  - **`m4-a3`** runs WP15's A3 acceptance test unchanged, snapshots the kernel's job records while it runs, and reports per-stage `wall_ms` and the promote total.
  - **`m5`** samples body RSS against mock request counts and applies the pass rule (OLS slope and max/base). It also gives a second-half slope as a diagnostic.
  - Results go to `measurements/<m>.json` with sorted keys; runs of the same `kind` are merged.
  - Safety: a disk guard stops below 5.3 GiB. Homes go under `target/test-homes/wp16/` and are removed by exact path. Only the tool's own children are signalled, through their handles.
- **Results:** `measurements/m1.json`, `m2.json`, `m4.json`, `m5.json`, `m5-100ms.json`, `phase0.md`.
