## Done
- **X0b, STRANDED-PROPOSAL and change states.** Proposal states gain `opening`, `open`, `rolled_back` and
  `collateral`. `verdict` is now actually set: on G4's final accept or reject, and on a `clean`, `quiet` or `flagged`
  close. Any path without a verdict returns the proposal to `screened` with a history entry:
  - a stale provisional or `initctl rollback`;
  - a failed promote job (init-kernel `EvoJob`): a G0–G3 failure, a refused change.open, a failed handoff;
  - a kernel restart: `promoted` (G4 lost as `kernel_restart`) or `opening` that never reached the Root;
  - a `collateral`, `suspect` or unattributed (H12 veto) rollback, once.

  A `direct` rollback, or a second rollback without a verdict, is terminal; this mirrors the Root's own re-admission
  rule. At kernel start, init-kernel `serve::start` calls `resume_proposals`, which uses only the Root's `by:"root"`
  `change_open` and `change_close` records from its published lineage view. A group the proposal was already open in
  is not resumed into again. A live proposal (`promoted`, `opening` or `open`) cannot be abandoned.
- **X0c, G3-STAGE-TIMEOUT.** The G3 bounds now derive from the build timeouts:
  - agent part = `g3.agent_timeout_s` + `build_timeout_cold_s` (the agent's `selfmap --write` builds cold in the
    probe);
  - the inner gate's clock starts after its own build (the slot's timeout bounds that build), so G0–G2 get
    `g3.inner_timeout_s`.

  The agent-wait rule is now a clock-free `AgentWait` state machine. A3 runs after the change goes live:
  - the body's own tests, read from the G0 record's `test` step;
  - then G3 for `t2` and `dep`.

  The first failure becomes `change.veto` of the group. A veto that fails is reported in the record, not hidden. A3
  takes the build slot and its own proxy gate.
- **X0d, the probe-root leak.** `ProbeRoot::delete` used to stop at EACCES. On EACCES it now gives every directory in
  the root owner `rwx`, using `lstat` and `fchmodat(AT_SYMLINK_NOFOLLOW)` so no link is followed, and removes it again.
  `probe.rs` no longer drops the error. `delete_root` logs it, writes an `alerts.jsonl` line
  (`source:"probe"`, `code:"probe_root_leak"`) and returns it as `ProbeOutcome.delete_error`.
- **X5 leftovers.**
  - kernel-proxy: `x-init-caps` (≤ 1 KiB) is forwarded as `x-egress-caps`, and the `x-init-*` original is never
    forwarded.
  - seed: `provider::caps::mark(id)` validates against the Root's grammar and refuses a 17th id or a header over
    1 KiB. `client::cx` takes the marks into `Cx.caps`, and `request_head` writes `x-init-caps` on every attempt.
    Compaction requests carry none. Seed components never mark.

## Deviations
1. "Verdict" on the free path means a `clean`, `quiet` or `flagged` close, or a `direct` rollback. A veto (H12,
   unattributed) counts as no verdict, as the Root's re-admission rule has it.
2. Gated restart: a `promoted` proposal whose provisional is still live returns to `screened` at once. Re-promoting
   that same sha still waits for its rollback, either `initctl rollback` or the 24 h expiry. No `--g4-only` verb.
3. A G0–G3 failure of a promote job also returns the proposal to `screened` (no G4 verdict), so the agent can re-gate
   after an infra fix. The validator is unchanged.
4. A3 vetoes on the body's tests only if A1 records them as advisory steps (K2's G0 on the free path). Today G0 fails
   hard on them.
5. RF-03 runs on a fake clock through the extracted `AgentWait` and `G3Bounds` rules, not on a live probe.
