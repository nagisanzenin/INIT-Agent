- **Scope (owner, 2026-11-01 ~20:40):** fix v0.5.5's §7.5 blocker at once and publish. v0.5.5 is an immutable release,
  so the fix ships as v0.5.6; E2, L5, M #1 and the rest of the planned v0.5.6 move to v0.5.7.
- The §7.5 review (on the public tree 3c21f5c) found:
  - **B1 (blocker, older than v0.5.5):** `clonefile(2)` on a folder above a protected path copies it to a readable
    name. Seatbelt checks a clone by its source only, and no zone tail denies `file-clone`, so a full-access agent
    could read the provider key files, `~/.init-release`, a `read_deny` entry, the Root's plist and ROOT_HOME (by
    cloning `~/.config`, `~/Library` or `$HOME`). Workspace mode is affected the same way (the folder above Chrome's
    profile), and so is the kernel profile (other instances' marks, Z5). The coordinator reproduced it with a minimal
    profile: `mv` denied, `clonefile` allowed and the key read; adding `file-clone` to the ancestor deny blocks it.
  - **S1:** the notes overstate two things: the "under a new name" reads are closed only for rename; and "a command you
    type is the system's" holds only when `~/.local/bin` was not already first on PATH (install.sh writes no block
    then).
  - **N1:** sealed/run.rs `body_home` copies GENESIS.md, SELF.md and self.json from the kernel-writable lineage tree
    with `is_file()` and `fs::copy`, which follow symlinks.
  - **N2:** the uninstall line fetches uninstall.sh from `main`, unsigned (older than v0.5.5; a Known limit for now).

## §7.5 post-release review (2026-11-02 ~00:10, the public tree 290e253)
**No blocker.** The reviewer established that `file-clone` is gated by `file-read*` at the source: a protected path
itself (the key folder, ROOT_HOME) was already unclonable, so the ancestor pin closes the gap; firmlink paths are
canonicalized. The sealed tail is deny-default with no `file-clone` allow (clone into a run root denied); the build,
check and git-read profiles all carry ZONE_TAIL. xattrs and named forks, searchfs, getattrlistbulk, Spotlight,
QuickLook, osascript and launchctl read metadata or reach mach services the tail denies; raw device reads are blocked
by DAC (predates). The T2 receipt's numbers and the bundle's size and sha256 match the notes.
- **Should-fix (low, predates v0.5.5):** `copy_regular`'s O_NOFOLLOW guards the last component only, so a link swapped
  in for `lineage/trees/<sha12>` between `real_dir` and the open is still followed (a race, not reproduced). Now a
  Known limit in the notes; v0.5.7 opens the folder with `O_NOFOLLOW|O_DIRECTORY` and copies through `openat`.
- Notes: "the tagged code is 930e354" cannot be checked in the public tree (its history is the exports); the notes
  now say it is the development repository's commit that latest.json names. The upgrade line's `~/.local/bin` is
  the default; get.sh prints the real path for a custom `INIT_BIN_DIR`.
