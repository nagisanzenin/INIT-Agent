## Root causes and fixes
1. **The cold build bound (release blocker).**
   - `DepsCache::commit` has no caller outside tests, so `cache/deps` is never populated and every promote build is cold.
   - A cold `init-body` build at `SANDBOX_CARGO_JOBS=2` took 500 s, 581 s and 634 s in this lane's runs and on the owner's machine, 877 s for the owner under load, and over 900 s twice. The default `build_timeout_cold_s` was 900.
   - Every real-install harness (`tests/real/*.sh`) ran with 3600/1800, so the shipped default was never qualified.
   - Fix a0306d7: defaults 3600/1800. The Root's `INSTALL_TIMEOUT_S` is 4500, so it stays above the kernel's cold bound.
2. **A seed test flake under load.** `run_group_separate_stdin_cancel` set cancel before `sh` had installed `trap '' TERM`. Under load the TERM killed `sh` and no KILL was needed, so `o.killed` was false. This failed G0 on the *unmodified* seed. Fix c346fa2: the test cancels after the trap marker, and seed/self.json was regenerated from a seedpack cut.
3. **G3 inner continuity (release blocker for every `Prefix-change: yes` candidate).**
   - G3's inner G2 checked continuity against the live body, which a prefix-changing candidate replaces by design. The outer G2 already waives that check.
   - The owner's `delegate` candidate passed G0–G2 on a fresh bundle install, then failed `gate.g3.inner_g2` (continuity, element 0).
   - Fix aa81e38: the inner G2 waives continuity when the candidate declared `Prefix-change: yes`. Its prefix must still equal the candidate's.
   - The new test `rel_g0_prefix_change_candidate_passes_g3` fails without the fix with the same error.
4. **The mock's probe detection (harness only).** In every G2 probe, the gate's stage notices (`[init:notice] gate: {...}`) follow the probe line, and `[init:signals]` follows the probe's tool result. In upstream mode the mock then saw a plain turn, and G2 failed with `parent_probe`. A real model is not affected. Fixes 07b5d6f and c46179c: the responder skips `[init:...]` annotations.

## The regression check: `scripts/bundle-e2e.sh --t2`
- Runs get.sh on the bundle with rustup on PATH, so the toolchain is recorded and the install is T2.
- Starts the Root, then commits a no-op comment on `evo/noop` in INIT_HOME/body as the agent identity, with self.json regenerated by `init-kernel selfmap --write --no-build`. With `--check`, the same call reproduces the seed's self.json byte for byte.
- The live agent, scripted through the mock, runs `initctl promote evo/noop`. The kernel socket refuses outside peers (`E_PEER`).
- Waits for the kernel's gate report. G0–G3 must all pass. The verdict goes to `build/status/bundle-e2e-t2.json`.
- Opt-in knobs, each one logged: `UBE_MOCK_BIN`, `UBE_COLD_BUILD_S`, `UBE_T2_FROM` + `UBE_T2_REF` (promote another commit), `UBE_T2_REPRO_EVENT`.
- A refused promote (validator or `E_*` error) fails within 60 s and shows the agent's initctl output.
- The verdict is read from the kernel's job record.
- The owner-state snapshot lists only names and modes for paths that an idle, running owner install rewrites on timers.
- With no knobs, on a bundle cut after these commits, the check should pass as shipped. It takes about 20–30 min and $0.
