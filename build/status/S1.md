## Harness (`scripts/slice1/`, `tests/slice1/`)
- `s1.sh <fakebody|mock|realdry|real> [--keep]` runs one isolated run under `target/slice1-homes/<f|m|d|r>/`. ROOT_HOME and INIT_HOME are 62 bytes each, within the 64-byte rule. The steps:
  1. Stage the binaries (overrides: `S1_ROOT_BIN`, `S1_KERNEL_BIN`, `S1_BODY_BIN`, `S1_MOCK_BIN`, `S1_FAKEBODY_BIN`).
  2. Start the mock.
  3. Write the charter: mirror off, `max_level 4`, $1.00/day and $1.00 total, `deepseek-flash`, `sealed.reserve 0`, and `test_mode` true for the mocks or false for real/realdry.
  4. Run `init-root install`.
  5. Write `kernel/config.toml`: `[sandbox]` equal to `install.json`, the price table, and soft budgets of $0.50, or $0.20 for real/realdry, with `request_max` $0.20. A $1 `request_max` would make the D6 clamp `ceiling − request_max` $0.
  6. Place the body and the key; start the Root.
  7. Wait for readiness; run `zonecheck.py`; read the balance; run `drive.py`; collect evidence; write the verdict.
  8. Run `collect.py`; `init-root stop`; SIGTERM the PIDs it spawned; remove the run dir by exact path.
- `drive.py` drives `init-root attach --raw`. The task is done at `state{busy:false}` after `busy:true`, because a `turn_end` follows every model turn. It polls `/_root/ceilings` every 0.5 s and `interrupt`s and `/stop`s above `S1_SPEND_MAX_MUSD`.
- `collect.py` redacts the key bytes, `sk-…`, `Bearer`/`x-api-key` values and the mock key, then rescans and fails on any leak.
- In real mode the key is deleted before collection and again in the EXIT trap.
- `tests/slice1/run.sh` is the $0 suite: fakebody, mock, watchdog, realdry, plus a leftover-process check.
- `scripts/slice1/s1-install.sh` is WP21b's variant (not mine).

## Gaps (harness workarounds still in place; not fixed in other crates)
1. **WP21b (install path) / WP4: no install-mode kernel.** `init-root install` never runs `init-kernel install --from-bundle`. The genesis tuple therefore has body `sha:""`, and the body exits 78: `{"code":78,"message":"INIT_SHA: \"\" is not a 40- or 64-hex sha","step":"env"}`.
   - Workaround: the harness writes the seed `state/kernel/lkg.json` that `init-kernel install` would write (reason `seed`, sha = repo HEAD as a stand-in seed commit, binary_sha256 = the staged body).
2. **WP21b / WP4: no `body/` checkout.** `INIT_HOME/body/` is empty, and the body exits 70: `head: …/ih/body/GENESIS.md: No such file or directory`.
   - Workaround: `git archive HEAD seed | tar -x -C ih/body --strip-components 1`. It has no `.git`, so the boot git sync is skipped, and there is no `lineage/body.git`.
3. **WP7b (kernel-serve) / WP6a (kernel profile): initctl is not served in the zone.** The kernel logs `{"c":"serve","msg":"initctl server not started: run/kernel.sock: Operation not permitted (os error 1)"}`, and the owner gets the alert `run/kernel.sock: Operation not permitted (os error 1)`.
   - `kernel.sb` allows `network-bind` under `RUN`, and `proxy.sock` binds fine, so some other operation on that path is denied.
   - This does not block Slice-1 (the body used no `initctl`), but the agent cannot reach its kernel commands.
4. **WP21 (performance):** Root cold start hashes every tuple blob before binding `owner.sock`. With debug sha2 that took 9 s for the 22 MB kernel and about 25 s for the 154 MB one (`sample`: 1504 of 1525 samples in `sha2::compress`). The harness waits up to 60 s.
   - Suggestion: bind `owner.sock` first, or cache the hashes by (dev, inode, mtime, size).
5. Resolved: WP13's awareness placeholders (`cap L?`, `ceiling ?`) are gone in the committed body, which now shows `cap L0` and `ceiling $1.00`.

## Deviations
1. **HOME.** `install` runs with `HOME=<run dir>`, so the LaunchAgent file lands inside the repo. `start` runs with the owner's real `HOME`, because the class rule compares the kernel's `passwd_home()` with the Root's `HOME` (`HOME_REAL`). The Root writes nothing under `HOME`.
2. **`keys set` reads only from a TTY**, so the key file is written directly (`tr -d '\r\n' < keyfile`, mode 0600) and checked with `init-root keys check`, which reports states only.
3. **Mock and fakebody runs used the shared test-fixtures Root until 04:46; the real run used a production build.** Both share the same code paths for charter `test_mode`.
4. **`zonecheck.py` has no canary probe.** The path form of `sandbox_check` is variadic, which ctypes cannot call on arm64. The canary and decoy denials are WP21's Z1/Z5 tests.
5. **Mock turn 2 expects `prefix:"same"` only.** The body correctly adds an `[init:signals]` user note after the tool results (log-context §3.13).
6. **Two free `GET user/balance` requests** (unmetered, $0) bracket the one paid task, to measure the cost outside our own meters.
