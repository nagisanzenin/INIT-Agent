## What it does
- **Admission (`change.open{scope:"k"}`)**: X3's plan (L1, no open group, one kernel change per day at L1), X6's A5,
  then **the Root conformance probe** (`kprobe::admit`, registered before X4's snapshot), then X4's system snapshot.
  `checks.K = "pass"` on the `change_open` record; a refusal is `extend.kernel_probe{step, why, exit}` and opens nothing.
  `candidate.kernel.source` must be `"agent"`. `current` does not move at admission (the swap moves it).
- **The probe**: a sealed run root laid out as a kernel home from `INIT_HOME/kernel/kupgrade-smoke/` (its `home/` tree,
  ≤ 8 MiB, and `config.toml`), the candidate `init-kernel` and `initctl` from the store, the LKG body (binary, T0,
  ext). The candidate runs under the sealed profile with the real control link on fds 3/4, against a probe Root that
  answers `hello` with `boot.reason = "kupgrade_smoke"` and `boot.probe = {kind, body_mode:"check"}`. Run 1: `hello`
  (proto 1) within 30 s, `ready` within 300 s, `ceilings.get`, the LKG body spawned with `INIT_MODE=check` writes `ready`
  and exits 0 (A4's 90 s rule), then exit 0 within `stop_grace_s` of `stop`. Run 2: `hello`, `ready`, then `ok` to
  `prepare_swap` and exit 75 within 10 s. Heartbeats every 30 s from `hello`; 3 malformed frames or a line over 1 MiB fail
  it. `store.put` is hashed and discarded, `lineage.append` kept nowhere. Takes the sealed OP lock (`root.busy` while a
  sealed operation runs). The root is removed by its exact path.
- **The swap (`system.swap{group?, init_kernel, initctl, version, source_repo, source_sha, report, measure?}`)**:
  - Free path: L1, else the demoting `root.level` refusal (D6 rule b, `ceiling_hit`); gated keeps L3. `root.mode` in
    safe mode, `root.busy` during a swap, and `root.unwatched_change` unless the binaries are an open, admitted kernel
    group's (no unannounced kernel). The body and ext must not have moved since admission.
  - `measure: ["gog"]` runs `sealed.gog` on the candidate's gate first; on the free path the result is a
    `kernel_upgrade{stage:"gog", pass}` record and decides nothing (`pass:null` when it could not run). Gated: mandatory,
    `gog_fail` ends the swap (the `mutation` record is R7's trigger there).
  - Phases: `prepare_swap{job, deadline_s}` (refusal, no answer in `swap_prepare_timeout_s` + 10 s, or no exit 75 within
    10 s of the answer → `aborted`, the group vetoed, the old kernel keeps running or restarts on the old tuple);
    exit 75 → install (`tuple`, so `current` moves; `installed`) → `ready` → probation (`kernel_probation_s`, Root
    clock) → `probation_pass`, after which body groups may open beside the kernel window.
  - Any exit of the new kernel in the ready wait or probation (crash, missing `hello`/`ready`/heartbeat, lost link) →
    `boot_fail`/`probation_fail` and the Root's whole-system rollback to the previous tuple with `boot.kstate` (the
    `kstate` blob the old kernel named in its `prepare_swap` answer). The sentinel's H1 on the same crash closes the
    kernel group as direct harm; its duplicate restart is dropped (`absorbs`), so the system restarts once. A rollback
    ordered elsewhere during probation (H2, H12, the owner) also gets `kstate` (`boot`).
  - Records: `kernel_upgrade{job, stage, group, from, to, kstate, source:"agent", …}` with stages `requested`, `gog` /
    `gog_pass` / `gog_fail`, `prepared`, `installed`, `ready`, `probation_pass`, `boot_fail`, `probation_fail`,
    `aborted`. The kernel gets `swap{job, stage, msg}` events. A Root restart aborts a job that had not installed and
    restarts the probation of one that had.
- **After probation** the kernel group's window is the sentinel's (40 turns, 120 h, at least 24 h). A rollback taking a
  kernel group is the Root's whole-system rollback at once (stop with grace, then kill): the new kernel is never asked to
  roll itself back, and a `body_rollback` confirms only a target that runs the current kernel. The H1 watch (R2 if the
  old kernel then crashes) is set for every kernel-group rollback.

## Deviations
1. **"Answer `ceilings.get`"** is read as: the candidate asks `ceilings.get` and receives the answer (it is a
   kernel → Root request; there is no Root → kernel form).
2. **The probe home is a sealed run root** (X4's deviation 1): the sealed profile, not the kernel profile, so the
   candidate has no egress socket, no `INIT_HOME` and no build slot in the probe. A conforming kernel's smoke path needs
   none of them. Its check body is spawned by the probe Root itself under the same profile (the kernel's `spawn` is
   validated: kind `body`, `INIT_MODE=check`).
3. **Probation and the prepare deadlines run on the Root clock** (fake clock in tests); the probe's bounds are real time.
4. **`lineage/kernel.git` is not updated by an agent swap** (root.md §3.8.1's sandboxed upload-pack fetch is not
   built); the tuple's `kernel.built_from` carries the candidate's claimed source commit. Phase 7 (LKG and audit) is the
   sentinel's window close on the free path.
5. **An aborted swap closes its group through the sentinel's veto** (H12, unattributed, re-admissible once), so the
   `harm` record says `H12` although the Root aborted.
6. **`kstate` is attached only to rollbacks during the swap and its probation** (root.md §3.8 phase 6). After probation
   the old kernel must read the new one's state (N−1 formats, supervise.md §3.15) and R2 (the system snapshot, taken at
   admission) is the escalation.
7. **A swap needs no owner turns or audit**; `SUPPORTED_MAX_LEVEL` stays 0 in release builds (ADR §7.2 says it rises to
   1 once X8's red-team rows pass; that is the owner's or orchestrator's call, not done here).
