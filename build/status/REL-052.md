- **§7.5 post-release review (2026-10-29 ~00:45), on public c083355. The findings, for the next patch:**
  1. **Lost files on `/undo` (class 2, pre-existing).** `access.rs` ~809 `restore()` runs `remove_dir_all` on the
     workspace's entries before cloning the snapshot back. A read-only directory in the workspace (for example a Go
     module cache, or a copy of an INIT release folder) stops it with EACCES after earlier entries are gone.
     Reproduced: `{main.go, zz.txt, vendor/pkg 0555}` left only `vendor`.
  2. **One shared `snapshots/.probe` (new in 0.5.2).** If it cannot be removed, every content check fails with
     EEXIST, so `/undo` falls back to the newest snapshot and the confirm step asks again. An unchanged launch leaves
     an orphan clone.
  3. **Free mode only:** the `/panic` warning compares `current` with `audited`, but the resume target is `settled`,
     then `lkg`.
  4. **A bare `init-agent upgrade` is printed** by get.sh (`up_agent`: "already installed" and "installed
     elsewhere"), by install.sh (~380, ~838), and in upgrade.rs's start-mid-upgrade message. The site says "then
     `init-agent --workspace`", and install-matrix asserts the bare form.
  5. **install.sh's PATH hint** always writes to `~/.zshrc`, which a Linux bash user never reads.
  6. **The `--upgrade` pipe without INIT_ROOT_HOME** on a custom-home install says "not installed … run without
     --upgrade". The second try is refused with the right line.
  7. The 10/10 receipt was missing here; it is recorded above.
  8. The cold-build numbers disagree: 788 s in v0.5.0 against v0.5.2's 1,831 s under load, and the new "10–20 min"
     dependency estimate.
  9. The site's /record Upgrade row omits 0.5.0.
  10. **Low:** the TUI's fixed command list refuses commands an evolved body adds, and a line starting with a
      one-segment path such as `/tmp`; the start-mid-upgrade check can exit 1 into a launchd restart loop; after an
      `/undo` and new edits, `/undo` restores the edits the owner already rejected.
  11. **Found by v0.5.3 lane A (§4.1 sibling grep), class 1, pre-existing:** snapshot.rs `restore_at` (R2, the system
      restore of body/, state/ and vault/) has the same remove-then-clone pattern. A read-only folder holding a file,
      which the agent can create under state/, makes the Root's R2 rollback fail half-way. The pre-restore clone is
      kept, so nothing is lost for good, but the rollback fails. `prune_at` leaks snapshot trees with read-only
      folders. Lane A fixes both in v0.5.3 (fix 7); the v0.5.3 notes must disclose it.
