# REL-051: v0.5.1-preview (security patch)

Opened 2026-10-28, after the post-release review of v0.5.0-preview (docs/release-protocol.md §7.5). This release
follows docs/release-protocol.md v1, which was written that day; it is the first release to run it end to end.

## Scope (§0)

- **Targets:** macOS arm64 and Linux x86_64, the same as v0.5.0. Linux aarch64 is still not shipped.
- **Live-tested providers:** DeepSeek only (unchanged). Anthropic and OpenAI stay experimental.
- **Disclosure** (the owner's decision, 2026-10-28): the workspace-mode hole is fixed first and disclosed in this
  release's notes. Nothing was published about it beforehand.

The fixes, from the independent review of the shipped v0.5.0 public tree (main 4e44929):

| # | Class | Finding | Lane |
|---|---|---|---|
| 1 | Root safety | In workspace mode the zone's git deny (zone-tail.sb Z3b) covered only `.git/config` and `.git/hooks`. Writing `.git/commondir`, renaming `.git`, or creating a `.git` file could point git at an agent-written config, whose `core.fsmonitor` then ran unsandboxed on the owner's next `git status`. | SANDBOX-GIT |
| 2 | Root safety | `get.sh --upgrade --from FILE` (`init-agent upgrade --bundle`) hashed a local bundle where the agent can write, then unpacked it from the same path, and could take its sha256 from a sidecar file the agent can write too. | UPGRADE-TRUST |
| 3 | Root safety (secondary) | The upgrade's `git bundle list-heads` inherited the owner's cwd. get.sh and install.sh `--upgrade` resolved tools on the owner's PATH. | UPGRADE-TRUST |
| 4 | Stranded user | `init-agent upgrade --version 0.5.0` returned 404, because the tag is `v0.5.0-preview`. | UPGRADE-TRUST |
| 5 | (rejected) | "$0.0005 per live DeepSeek turn" was reported as flattering. The review read the Root µUSD column of real-v0.1.md, which predates the cache-read price. The provider bills (the proxy column) are $0.0002–0.0012 per turn on real tasks, so the number stands. | none |
| 6 | Stale label | The site's "40 s from install to first reply" lacked "on a fast link". The site was fixed the same day (init-labs 1509f02). | none |

## The user sessions on v0.5.0 (§5.7, run 2026-10-28 before this release)

`docs/user-sessions/v0.5.0-new.md` and `v0.5.0-returning.md`. Each was a persona agent in a fresh context, driving a
real TUI through tmux on the mock. **Both verdicts: do not ship.**

Part of each verdict came from harness artifacts:
- The project folder was outside the passwd home, so the session had no workspace.
- The Root was restarted from a shell with the test HOME.

The harness rules are now in §5.7. The product bugs behind the verdicts:
- **Tab on `/` completed to `/panic`, which ran with no confirmation.**
- Bare `init-root …` commands were printed, and `init-root` is not on PATH.
- `/usage` showed "evolution checks today $0.00" while about $0.03 of probe and G3 calls were metered.
- An answered `ask_owner` question returned after a relaunch.
- Jargon refusals had no next step.
- Labels disagreed: the G0 timer against its row, "G4 pass 0.0 s" in free mode, $0.05 against $0.04, ceilings
  against "caps off", and a record count off by one.
- The no-workspace state never said where the agent works.
- A panic and resume after an upgrade possibly ran the pre-upgrade tuple (plausible; under investigation).

Lanes TUI-FIX, ROOT-MSG and ROOT-TUPLE own these. The sessions run again on the v0.5.1 candidate.

### §4.3 adversarial review
- **Z3b, run by the orchestrator** (2026-10-28 ~14:40). The first reviewer for this area stopped without results. A
  reviewer that does not report is an unrun gate, so this part was run directly. The test was a profile with exactly
  the candidate's Z3b lines, `(allow default)` before them, and a scratch repository on the boot APFS volume, which is
  case-insensitive. Every write below was denied:
  - `.git/commondir`, `COMMONDIR` and `CommonDir`;
  - `config.worktree` and `CONFIG.WORKTREE`;
  - `gitdir` and `GITDIR`;
  - `mkdir .git/MODULES` and `.git/WORKTREES`;
  - renaming `.git` to `.GIT` (a change of case only);
  - a hard link to `.git/config`, and a hard link to a hook;
  - a write through a symlink to `.git/config`.

  Seatbelt matches these names regardless of case on that volume, so the lower-case rules cover the upper-case
  spellings that git also reads there.
