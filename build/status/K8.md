## Findings (blockers for "the real init-kernel passes the Root probe")
1. **The probe's check body cannot boot the real seed body.** `kprobe::spawn_body` writes a fresh
   `state/kernel/boot.json` without `model`; the seed's `read_boot_json` requires `model.{provider, model}` and exits 78
   ("boot.json model is missing"), so the probe fails at step `body` even for a conforming kernel. X4's A4 probe does not
   have this bug: it merges into the existing boot.json. Fix (Root, small): merge like A4 (start from the probe root's
   boot.json, which the candidate kernel writes before `spawn`, else the live `INIT_HOME/state/kernel/boot.json`, then
   override the identity fields). `INIT_PROXY_SOCK` is fine (`sealed::sandboxed` sets it).
2. **The real kernel has no smoke path.** On `boot.reason = "kupgrade_smoke"` it runs the full cold start (proxy on a
   missing egress socket, layout and git checks, tuple restore via `store.get`, which the probe answers
   `root.unknown_cmd`), so it never reaches the probe's steps. Its `prepare_swap` answer is `{}` (no `kstate`), and
   nothing restores `boot.kstate`.

## Plan (next steps, in order)
1. **Smoke path** (`kernel-supervise/src/kupgrade.rs`, hook in `supervisor.rs` `cold_start` right after `hello`): when
   `boot.reason == SMOKE_REASON`, skip the cold start (no proxy, layout, lineage, LKG rebuild); start `hb`; `ready`;
   `ceilings.get`; write a boot.json and `spawn` `$INIT_HOME/bin/init-body` (kind `body`, `INIT_MODE=check`) through the
   real `Spawner`; drain its stdio; wait for its `exited` (≤ 90 s); then serve Root requests: `stop` → answer `ok`, exit
   0; `prepare_swap` → (stop any check body) kstate, answer `ok{kstate}`, exit 75; link lost → 69; wall bound → 70.
   Requests that arrive between steps (run 2 sends `prepare_swap` right after `ready`) are handled at once.
2. **kstate** (root.md §3.8 phase 3/6): in `Supervisor::exec`, when an action list holds `Respond{Ok}` + `Exit(75)`,
   tar `state/kernel/` (regular files, deterministic ustar/pax as `t0blob`, excluding `logs/`, `vendor/`, `gate/`,
   `probe/`; cap 64 MiB, over it: no kstate and an alert), `store.put{kind:"kstate", job}` and answer `{"kstate": sha}`.
   At cold start, if `boot.kstate` is set: `store.get`, strict tar read (relative paths, no `..`, regular files only)
   into `state/kernel.kstate/`, then replace the non-excluded top-level entries of `state/kernel/` (exact paths), before
   anything reads `state/kernel/`.
3. **Root probe fix** (finding 1) in `kprobe.rs`, coordinated with X8-KLANE.
4. **Free-path `kernel promote`**: `kernel-serve` gating needs L1 (not L3) for `kernel.promote` when `extend_free`;
   `init-kernel serve.rs` `kernel_promote` → `kupgrade::promote_free`: `check_request_in(free, …)`, the K2 validator on
   the `kevo/<id>` commit in `work/kernel`, K0 (see deviation proposal), `store.put` init-kernel and initctl,
   `change.open{scope:"k", candidate{body, ext: current tuple, kernel{built_from, init_kernel, initctl, source:"agent",
   version}}, caps:[kernel/*]}` with K2's refusal map, the group in `extend/groups.json` (scope `k`), then
   `system.swap{group, …}`; the job succeeds with `root_job` once the Root accepts the swap (the old kernel then
   pauses the body at its next step boundary and exits 75).
5. **Tests ($0)**, new `kernel/crates/init-testkit/tests/k8_real_root.rs` (ignored by default, like `x2_real_root`): the
   real init-kernel admitted through the real Root's probe (`checks.K = pass`); the L1 e2e (test ledger at L1, mock
   model drives `initctl kernel promote kevo/trivial --wait`; probe, swap, `kstate`, probation via `test clock`, the
   kernel window closes clean or quiet); a broken candidate (e.g. `init-fakekernel`, which has no smoke path) refused
   with `extend.kernel_probe` and nothing opened. Unit tests for the kstate tar round trip and the smoke step order.
6. Only after 5 passes, and on the owner's decision: `SUPPORTED_MAX_LEVEL` 0 → 1 (release builds).

## Deviation proposals (not applied)
- **K0 build**: `lineage/kernel.git` is created empty at install (the release source import is WP21/WP23 and not
  built), so a kernel-run K0 from source cannot work on real homes yet, and a K0 build in a test home would need a fresh
  kernel target dir (≈ 1.5–3 GB; not affordable at about 7–13 GB free, and a new target dir needs the orchestrator's OK).
  Proposal: K0 as a cargo build in a `build` instance (production path), plus a test-mode seam that takes prebuilt
  binaries (honoured only with kernel `test_mode`), recorded in the v5 gate record as `k0: "prebuilt (test)"`. K0 is
  quality-only under ADR-011 (the Root probe is the safety check), so the seam does not weaken a safety property.
