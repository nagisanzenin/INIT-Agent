# SBX-009: ADR-009 permissions, the Root and sandbox side

Status: **done** (2026-10-20, lane SBX-009), except doc_drift, which waits for DOC-009 to copy the two texts. Spec: `build/specs/ADR-009-spec.md`.

## Protocol for WIRE-009 (binding; written first)

Everything below is what `init-root` accepts and sends. Framing, the peer check and the error shape are
today's (root/root.md §4.1, §4.2): request `{"v":1,"id","cmd","args"}`, answer `{"v":1,"id","ok":true,"result"}`
or `{"v":1,"id","ok":false,"error":{"code","message","details":[],"data"}}`. Every object is ICJ (sorted keys).

### A. owner.sock request frames

| `cmd` | `args` | `result` | Errors |
|---|---|---|---|
| `workspace.set` | `{"cwd": "<absolute path: the TUI's cwd>"}` | `{"access": AccessView, "changed": bool, "refused": null \| {"code": Reason, "message": "<text>"}}` | `root.args` (cwd missing / not a string) |
| `full.set` | `{"on": bool, "confirm"?: "<what the owner typed>"}` | `{"access": AccessView, "changed": bool, "snapshot": Snap \| null}` | `root.mode` with `data:{"reason":"charter"}` (charter `sandbox.allow_full = false`); `root.confirm` (below) |
| `undo` | `{"confirm"?: "<what the owner typed>"}` | `{"restored": Snap, "saved": Snap}` | `root.mode` with `data:{"reason":"no_workspace"}`; `root.not_found` (no snapshot); `root.busy` with `data:{"reason":"body_busy"}` (a turn is running: checked first, before the confirmation); `root.confirm` (below); `root.internal` |
| `access.get` | `{}` | `AccessView` | — |
| `status` (existing) | `{}` | gains the key `"access": AccessView` | — |

- **`workspace.set`** is sent once per `init` launch, right after the first attach, before any owner line. Each call
  starts a new owner session: full mode turns off and its confirmation is forgotten. `cwd` is sent as the OS gives it;
  the Root canonicalizes and validates it (spec item 2). An invalid cwd, or the home itself, is **not** an error: the
  workspace becomes none and `refused` says why. `Reason` ∈ `relative` `missing` `not_dir` `outside_home` `home`
  `root_path` (inside or containing ROOT_HOME, INIT_HOME or `~/Library/LaunchAgents`) `deny_list` `too_long`.
  When the workspace changes, the Root takes the session snapshot (spec item 4) before answering.
- **Typed confirmation (`root.confirm`).** `full.set{on:true}` the first time in a session, and every `undo`, answer
  `{"code":"root.confirm","message":"<what it will do; ask the owner to type the phrase>","details":[],"data":{"phrase":"confirm", …}}`
  unless `args.confirm` equals `data.phrase` exactly. The client shows `message`, reads one line from the owner and
  resends the same request with `"confirm": <that line>`. For `undo`, `data` also holds `"snapshot": Snap` (what will
  be restored). The phrase comes from `data.phrase`; do not hard-code it.
- `full.set{on:false}` never needs a confirmation.

```text
AccessView = {"access": "none"|"read_home"|"workspace"|"full", "allow_full": bool, "full": bool, "read_home": bool,
              "restart_pending": bool, "snapshot": Snap|null, "workspace": "<canonical path>"|null}
Snap       = {"at": "<RFC 3339>", "id": "<snapshot dir name>", "reason": "session"|"full_on"|"pre_undo", "workspace": "<path>"}
```
`access` is what a new live body gets: `full` (full mode on), else `workspace` (a workspace is set), else `read_home`
(charter `sandbox.read_home`, default true), else `none` (the v0.1 behaviour). `restart_pending` is true from a change
until the next live body spawns with the new grant. `snapshot` is the latest snapshot of the current workspace.
The TUI status bar shows `FULL` while `access.full` is true (poll `status` as today; also refresh on a notice with
`code:"access"`).

### B. Owner lines the Root handles itself (attach channel `line{text}`, exact match after trimming)

`/workspace` (shows the AccessView as text), `/full` (same), `/full on`, `/full on confirm`, `/full off`, `/undo`,
`/undo confirm`. Answers are `notice` frames. `/full on` and `/undo` reply with a notice that says what will happen and
asks for `/full on confirm` or `/undo confirm`. So a client may simply forward these lines; the request frames of A
are the structured form of the same operations.

### C. Notices (Root → every attached client, `src:"root"`)

- `code:"access"`: every workspace or full-mode change. Texts: `[root] workspace: <path>`,
  `[root] no workspace: cd into a project and run init to let me edit it` (`refused` set or launched in `~`),
  `[root] full mode on: …` / `[root] full mode off …`.
- `code:"snapshot"`: a snapshot taken, skipped (over 2 GiB, not APFS, other volume) or restored by `/undo`.

### D. Control link (Root ↔ kernel)

- The `hello` result (boot block) gains `"access": {"access": …, "full": bool, "workspace": "<path>"|null}`.
- New **Root → kernel event** `{"v":1,"ev":"access","data":{"access": …, "full": bool, "restart": "idle"|null, "workspace": "<path>"|null}}`,
  sent after every `ready` (`restart: null`) and on every change (`restart: "idle"` when the live body's grant
  changed). On `"idle"` the kernel restarts the live body gracefully at its next idle boundary; the body resumes its
  session log (spec item 5). Unknown fields must be ignored.
- **Body spawns are unchanged on the wire.** The kernel sends the same `spawn` params as today and **no** new param:
  the Root adds its own `Z_HOME`/`Z_WRITE` (parameters of the Root's texts, never kernel-supplied; V1 already refuses
  `Z_*`). For every `body`-profile spawn (kind `body` or `probe`) the Root **sets `INIT_WORKSPACE`** (`""` when none)
  **and `INIT_ACCESS`** in the child's env, overwriting any value the kernel sent, so they always match that
  instance's sandbox. `cwd` must still lie under INIT_HOME (V4 unchanged): tools should `chdir` to
  `$INIT_WORKSPACE` when it is non-empty.
- **Who gets what** (decided by the Root from `kind` and the `INIT_HOME` param's lane):

  | Instance | Read | Write (beyond today's INIT_HOME rules) | `INIT_ACCESS` |
  |---|---|---|---|
  | live body (kind `body`, lane live, incl. safe mode) | home minus the deny list, if `read_home` or full | the workspace; the whole home minus the deny list and Root paths in full mode | as AccessView |
  | fleet member (kind `body`, `fleet/<bid>`) | home minus the deny list, if `read_home` | none | `read_home` or `none`; `INIT_WORKSPACE=""` |
  | probe (kind `probe`) | none (hermetic, as v0.1) | none | `none`; `INIT_WORKSPACE=""` |
  | kernel, build, check, git-read | unchanged (the deny list now applies to them too, via tail Z2) | unchanged | — |

## Deviations
1. The three `[sandbox]` keys are omitted from the effective charter JSON while they hold their defaults, so a v0.1.0
   charter keeps its digest (lineage `charter` records, `hello.charter_sha256`). root.md says "with defaults".
2. `read_deny` entries must be absolute (no `~/`), and may be neither an ancestor of, equal to, nor inside INIT_HOME
   (stricter than DOC-009's "not an ancestor").
3. A snapshot is taken at every `workspace.set` that sets a workspace (each `init` launch is a session), not only when
   the workspace changes: spec item 4 says "the first agent turn … in a session".
4. `INIT_ACCESS` has a fourth value, `none` (`read_home = false` and no workspace), as the protocol says.
5. Write grants stop at INIT_HOME (`require-not`), so even full mode cannot write `bin/`, `lineage/`, `cache/`,
   `vault/` or `state/kernel/`.
6. The workspace must also not lie inside a write-deny entry (`deny_list`), e.g. `~/bin/x` or `~/.config/fish`.
7. The home is `$HOME` of the Root process (`Paths.home`, as `HOME_REAL` already was), not `getpwuid`.

## Residual risk (for the ADR; full mode, and the workspace in every mode)
Z3a/Z3b close the obvious unsandboxed-execution paths. What remains writable and may later run as the owner:
- in the workspace (every mode): build and task files the owner runs (`Makefile`, `package.json` scripts, `build.rs`,
  `.envrc` for direnv, `.vscode/tasks.json`, `.idea/` run configs, test files); a `.git` *file* (`gitdir:`) pointing at
  a git dir elsewhere in the workspace, whose `hooks/` the regex does not cover (Codex has the same gap);
- in full mode: editor startup files (`.vimrc`, `.config/nvim`, `.emacs.d`, VS Code `settings.json` and extensions);
  language user-site dirs (`~/Library/Python/*/lib/python/site-packages` with `.pth` files, `~/.cargo/bin`,
  `~/.npm-global`, `~/go/bin`, `~/.rustup`); tools that run configured commands (`~/.tmux.conf` `run-shell`,
  Hammerspoon `~/.hammerspoon/init.lua`, `~/.config/karabiner`); apps under `~/Library/Application Support/` that load
  plugins; and every directory on the owner's PATH other than `~/.local/bin` and `~/bin`. (`~/.ssh/config` is covered:
  the read deny list denies writes too.)
- `/undo` and agent writes can race: the busy check uses the last 5 s `hb`, so a turn that starts during a restore can
  still write.
