## Deviations
1. **Probe 7(b) makes 2 requests, not 3:** after a text-only reply to the nudge there are no results to send, and a third request would end on an assistant turn. When the model never calls a tool, `bash true` runs directly (unlogged) as boot.md §5 says, `model_called_tool:false`, `tool_round_trip:false`.
2. **The probe driver lives in boot**, composed from the loop's public seams (above), not `Session` internals; only the batch policy differs. `tool_round_trip` = a request carrying tool results came back `Done`.
3. **New test-only knobs** (under `INIT_TEST=1`): `INIT_TEST_LOCK_WAIT_MS` (§8 item 3's "test override"); `INIT_FAULT` adds the body action `panic` and boot points `boot.after_env`, `boot.after_boot_event`, `boot.before_ready`.
4. **Constitution seed copy** at `seed/src/boot/CONSTITUTION.md` (inside the crate, so the installed body stays self-contained and no editable `body/CONSTITUTION.md` shadows the real `kernel/CONSTITUTION.md`). CONVENTIONS §2 names a repo-root `CONSTITUTION.md`: copy these bytes there if wanted.
5. **Root status rendering** goes through `rootview.rs` (Slice-1 readiness). `boot.cause` objects are logged as their `kind` string (the schema's enum); `from_sha`/`lkg_sha` are copied only when they are valid shas.
6. **Git sync** (helper A) runs nothing unless `body/.git` exists and sets `GIT_CEILING_DIRECTORIES` (test homes sit inside this checkout); a timeout stops the script; `main` moves only after `rolled-back/<sha12>` is created; refused ff and failed pop are warnings, not `error`.
7. **Awareness** (helper B): the capability recipe reads `state/kernel/self.json` (D12); `env_changed` ignores `disk_free_mb` moves < 1,024 MB and `root`-only changes; a stats failure keeps the Root's ceiling on the signal line; the level-change line also shows on a session's first boot; owner offset from `env.budget.day_starts_at` (the Root's offset wins when present).
8. **Head errors exit 70** (crash path), per awareness §5.
