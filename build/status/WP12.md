## Deviations
1. **File layout.** The modules are directories (`src/log/`, `src/context/`). The SHA-256 is in `src/sha256.rs`, which is where log-context §3.10.4 names it.
2. **Inputs are log-level mirrors.** The context takes `AssistantIn`, `BoundaryIn`, `ResultIn`, `OwnerIn`, `NoticeIn`, `ReloadIn` and `CallStart` rather than provider.md's and loop.md's types (WP10/WP11 not built yet). `ContextHooks` is not declared here; `Context` has the same methods.
3. **Step order.** Rehydration reads `request.k_ppm` (step 10) before writing the synthetic results (step 9), so their `tokens_est` uses the recovered k.
4. **Empty files.** An existing session file that is empty or fully corrupt gets a new `session` header, so the session has a root.
5. **`mask.masked[]` additions.** Masked-input entries add `call_id` and `input` (the masked input object, replayed as ICJ in place of the raw arguments). The schema allows extra fields. A string in a masked input is "long" above 64 tokens; the doc gives no number.
6. **Image masking.** An output is masked when its *text* part is ≥ 256 tokens (or ≥ 2,000 for errors). Otherwise its images are masked as part `image`. The doc's "any size" rule is kept.
7. **Placeholder and summary formats.** In placeholders, `read` line ranges come from the `[Showing lines S-E` trailer, else from offset plus the count of numbered lines, and token counts are plain integers. The summary header uses `,` separators, as in the doc example. Owner-message lines use the full 16-hex id and seconds-precision `ts`, end in `…` when cut, and start with `- (+N older; see the log)` when there are more. "Commits and gates" has one row per `self_edit`/`gate` event (`gate G2 3f2a1c0 pass (event …)`), not the doc's merged-per-commit row.
8. **Retries.** At most one format retry (step 4) and one id retry (step 5), so up to 2. Duplicate ids are renumbered to the next free number of their letter; the new ids go in `repaired_ids` after the restored ones.
9. **Inflation check with one huge last step.** The check counts the tail masking that follows the compaction; otherwise the §3.12.2 case could never pass step 8. The thrash guard's hard window is `model_window − max_output`.
10. **Signals.** The context always fills `ctx_tokens`/`ctx_permille` itself. A pending signal is dropped on `/branch` and `/new`, because its batch is off the path.
11. **Resume with no failure.** The leaf still returns to the paused leaf, leaving B1's events off the path.
12. **Fallback `update_failed` text.** `[init:update-failed] The update to <sha7> failed at <stage>: <reason>. …` is used only when no rendered text is supplied.
13. **Golden source.** T-CTX-2's golden uses snapshot copies in `src/context/testdata/head/` (seed GENESIS.md and SELF.md, the awareness §3.3 constitution draft, one test skill) and `testdata/tools.json` (tools.md §4.1, 3,405 bytes). Edits to the seed files therefore do not silently break it. Re-bless with `INIT_WP12_BLESS=1`.
14. **Head object.** A missing `tools` key hashes as `null` (INIT always sends tools).
