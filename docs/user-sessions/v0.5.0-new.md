WHAT WORKED
- First run was fast and clear. `init-agent`, then a provider picker (DeepSeek "recommended"), a hidden key prompt ("goes only to the Root (stored 0600), never to the agent"), a model picker with prices, then "Setup done. Type a message to start." Under a minute.
- The agent's question came up as a numbered picker ("1. Write it and run it  recommended"). Easy to answer.
- The self-change showed a live gate track (G0 build + tests, G1 self-map, G2 boot probe, G3 self-edit probe, goes live, G4) and ended with a clear line: "✓ kept 60ec48547cf3 · 5/5 gates · 17 min 47 s · no restart".
- The cost was always in the status bar, and `/usage` gave a full breakdown. The TUI's token math adds up: 12.3k + 25.5k + 85.5k = 123.3k in, 47 + 115 + 555 = 717 out, 94208/123300 = 76.4% cached.
- `?` gives a good key list. Ctrl-O shows the transcript and a signed lineage ("verify ✓ 9 records · every signature").

WHAT CONFUSED ME
- First screen: "[root] no workspace (nothing has /undo)". I was in `~/demo`. Nothing said what a workspace is or how to get one.
- The agent said "Done: hello.py is in this folder". The bash line showed `... > hello.py && python3 hello.py && ls -l hello.py ✓ exit 0, 2 lines`. After quitting, `ls -la` in ~/demo showed an empty folder, last modified 11:48, before I started. `find ~ -name hello.py` found nothing. The "Done" text is the test model's script. But the shell tool really ran and succeeded somewhere other than my start folder, and the screen never said where. Its 2 output lines were folded away.
- `init-agent --workspace` printed "[root] no workspace: cd into a project and run init-agent to let me edit it". The status bar showed "no workspace · WORKSPACE" at the same time, and the model name disappeared from it.
- Gate symbols □ ■ · are never explained. "G4 scored vs LKG": I don't know what LKG is. The status bar "body ee962a5dd4da lkg" didn't change to the new id until my next message.
- After a relaunch the history replays, then the old, already-answered "agent asks · Run it?" picker pops up again. After Esc the bottom bar still said "waiting on you · the agent asked a question (above)".

**Harness artifacts, and the real problem under each:**
- *"no workspace", `hello.py` not in `~/demo`, the `/undo` dead end.*
  - Cause: the Root's HOME_REAL is the passwd home, `/Users/…`, and the persona's project sat in `/private/tmp/i5-us1/h/demo`, outside it. The Root refuses a workspace outside the home (root/crates/init-root/src/access.rs), so the agent worked in `INIT_HOME/work`; `hello.py` was found at `/private/tmp/i5-us1/i/work/hello.py`.
  - On a real Mac a project inside the home gets a workspace, so the trigger is an artifact.
  - Still real for any user who starts in `/tmp`, `/Volumes/…`, `/opt` or `~` itself:
    - the refusal never states the rule ("a folder inside your home, not your home itself");
    - with no workspace, the screen never says where the agent works;
    - `/undo`'s advice ("cd into a project and run init-agent") does not help;
    - `init-agent --workspace` starts anyway, showing "no workspace · WORKSPACE".
- *"live" on the mock:* the labels are test-mode only.

**Product bugs, independent of the harness:**
1. **Tab on `/` completes to `/panic`, which runs with no confirmation.** CONFIRMED in code.
   - `COMMANDS` lists `/panic` first (tui/crates/init-tui/src/proto.rs:207), and Tab takes the selected candidate, the first one by default (tui/crates/init-tui/src/input.rs:280).
   - One Enter later the whole system stops and drops a level. Medium-high.
2. **The answered `ask_owner` picker comes back after a relaunch**, and "waiting on you" stays after Esc. CONFIRMED on screen. Medium.
3. **The evolution-check cost shows $0.00** (the table above). Medium, class 4.
4. **No ETA on the gate.** It ran 17 min 47 s on a cold first T1, with no estimate. Low-medium.
5. **Ctrl-D leaves a half-drawn input box**, says nothing on quit, and gives no word on what keeps running. Low.

**The verdict stands: do not ship, as it is binding.** Of the persona's three blockers, the first two come from the harness's workspace location, but their messages are real problems; the third (Tab → /panic) is a real bug.
