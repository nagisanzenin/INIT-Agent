## User session — v0.5.3 — RETURNING (had 0.5.2, upgrades to 0.5.3)
PROVENANCE: An AI persona agent (Claude Opus 5.5) played the user by driving tmux on a test Mac. The model was scripted, the paths were redirected by the harness, there was no LaunchAgent and the bundle was local, not fetched from GitHub. This can certify the screens and the flow for upgrading 0.5.2 to 0.5.3 with the Root running in a terminal, the TUI, and /undo. It cannot certify real model behaviour, the real download, the LaunchAgent path, or the signature check.
target: macOS arm64   model: mock (scripted)   real minutes: 5

WHAT WORKED
- The upgrade worked on my second try: "INIT is upgraded to v0.5.3 (18 s). Kept as they were: the body INIT evolved, its extensions, the sessions, the lineage, your keys and your charter."
- When it refused the first time, it told me exactly why and what to do, and "Nothing was changed."
- At the end it printed the exact line to restart the Root. I pasted it and the Root came up as 0.5.3.
- Plain `init-agent` opened the TUI, which showed "INIT 0.5.3 · L0 · root ok".
- The done command works. `done 2` marked item 2. `done 9` and `done x` both printed "usage: todo.py add TEXT | list | done N" and exited 2.
- /undo list was clear. It marked the snapshot that matched my folder "same as the folder now" and pointed /undo at the one before the agent's change.
- /undo asked me to type `confirm` first and warned that my own edits would be replaced too. It saved the current folder first and told me the id that brings it back. My folder went back exactly: todo.py at 696 bytes with no done command, and both items back to [ ].

WHAT CONFUSED ME
- The release page's Upgrade section doesn't say you have to stop a Root that runs in a terminal first. I only found out when the upgrade refused.
- The step counters jump: "1/7 preflight", "2/7 release binaries", then "upgrade 1/5" through "upgrade 5/5". I never saw steps 3/7 to 7/7.
- "Not done by this release: offering its new seed to INIT." I have no idea what that means or whether I should do something.
- The upgrade output has raw JSON blobs in it, and the Root's startup line is one huge JSON blob ("day_musd":5000000 ...). I can't read either.
- On the first launch the TUI showed nothing of last week's conversation, yet the agent carried on as if it remembered. When I reopened later, it did show tonight's conversation. So I couldn't tell whether last week's session survived the upgrade.
- The agent said "I tried it on your list (above)", but nothing was visible above. The output was folded into "✓ exit 0, 2 lines" and I had to press Ctrl-O to see it.

WHAT ANNOYED ME, and what I would have quit over
- The agent ran `done 1` on my real todo.json and marked "buy milk" done without asking me. (The reply is canned here, so this may be the test model rather than INIT.)
- After /undo, `ls` showed the group on both files changed from staff to wheel.
- The /undo result was printed twice, once as a [root] line and once as a TUI line.
- When I closed the TUI it told me to run "INIT_ROOT_HOME=/private/tmp/i5-us53-b/r /private/tmp/i5-us53-b/b/init-agent" to come back, but plain `init-agent` worked fine.
- Nothing would have made me quit.

WHAT IT TOLD ME vs WHAT WAS TRUE
- Versions agree everywhere I looked. The Root said "0.5.2" before and "0.5.3" after, the TUI said "INIT 0.5.3", and the upgrade said "v0.5.3" and "0.5.3-preview".
- Cost and token totals add up:
  - Before tonight: $0.004 and 24487 tokens.
  - My turn: in 26.0k, out 115, $0.001.
  - Afterwards: $0.005 total, and /usage showed "input 50400, output 202". 24487 + 26115 = 50602 = 50400 + 202.
- Cache: the status bar said 90.5%, but /usage's own numbers (23552 / 26000) work out to 90.58%. It looks truncated rather than rounded. Tiny.
- The details view showed "in 13200 (cached 11776), out 61" while the status bar showed 26.0k. /usage explained it: the turn was "2 requests".
- After I reopened the TUI, the turn's cost changed from "$0.001" to "$? before this launch". The number got worse just because I reattached.
- /usage said "this TUI 2 requests" for a turn it also says "ran, at least in part, before this TUI attached". That contradicts itself.
- Lineage numbers only went up, which looks consistent: seq 5, then "9 records, head seq 8", "15 records, head seq 14", seq 16, and finally "verify ✓ 20 records (seq 0–19)". I don't know why stopping and upgrading added these records, and I can't check them myself.
- Signing: the release page says 0.5.3 releases are signed and gives the fingerprint SHA256:IS7wIWkppZkHSUwdnsJR+K4fBPkmPa/IJwfNi9sIoMs. Nothing on my screen mentioned a signature or that fingerprint, only "checksum matches" and "every file matches SHA256SUMS". That may be expected, since the page says the check starts "from 0.5.3 on", but I had no way to compare the fingerprint.
- Dates: the release page is dated 2026-10-30, but my clock says 10-29.
- The README "announces 0.5.3", but its "Tested" section only talks about v0.5.2.
- Nothing looked too good to be true.

EVERY COMMAND I WAS TOLD TO TYPE
1. Release page: `env -i HOME="$HOME" ~/.local/bin/init-agent upgrade`. The first try failed: "install.sh: the Root (pid 65526) runs without the service. Stop it in its terminal (Ctrl-C), then run the upgrade again. Nothing was changed." The second try worked in 18 s.
2. Upgrade screen: Ctrl-C in the Root's terminal. Worked.
3. Upgrade screen: `INIT_ROOT_HOME=/private/tmp/i5-us53-b/r /private/tmp/i5-us53-b/r/bin/init-root start --foreground`. Worked; the Root came up as 0.5.3.
4. Upgrade screen and the Root's window: "Open INIT: /private/tmp/i5-us53-b/b/init-agent". I typed plain `init-agent` instead, which was on my PATH from last week, and it worked.
5. Agent: `python3 todo.py done 1`. Worked.
6. TUI: `/undo list`, then `/undo`, then `confirm`. All worked.
7. On closing the TUI: "INIT_ROOT_HOME=/private/tmp/i5-us53-b/r /private/tmp/i5-us53-b/b/init-agent" to come back. I didn't need it, because plain `init-agent` worked.
8. Not used: the README's curl get.sh install line and the release page's 0.5.0/0.4.1 curl line. Neither applies to a 0.5.2 user.

WOULD A STRANGER GET THROUGH THIS?   yes
There is one stumble: the upgrade refuses while the Root runs in a terminal. The refusal says exactly what to do and changes nothing, and the end of the upgrade prints the restart line. Nobody would know what the "new seed" line means, but you can safely ignore it.

VERDICT: ship
Before or soon after release:
- Add one line to the release page's Upgrade section about stopping a Root that runs in a terminal (Ctrl-C) first.
- Explain or drop "offering its new seed to INIT".
- Stop the turn's cost turning into "$?" after the TUI is reopened.
