# INIT Agent v0.3.3-preview

*2026-10-25 · research preview · macOS (Apple silicon) and Linux aarch64 (experimental)*

INIT is a harness in which a coding agent may rewrite itself, including its compiled core. It runs under a Root, a separate process the agent cannot change. The Root holds the keys, the sandbox and a signed record of every change, and it can always roll the agent back to its last known-good version.

This is a research preview, not a finished product. Everything in [v0.3.2-preview](v0.3.2-preview.md) and [v0.3.1-preview](v0.3.1-preview.md) still applies (Esc and Ctrl-C pause, full access by default, how to confine it, the known limits).

## DeepSeek: resuming a paused turn no longer costs a refused request

In v0.3.2, if you paused a turn (Esc or Ctrl-C) before the model's first token, the agent kept an empty reply in its history, replayed as `[no visible output]` with no `reasoning_content`. DeepSeek in thinking mode with tools requires that field on every assistant message, so the first request after you resumed was refused (HTTP 400, no tokens billed), and a documented fallback retried it with an empty field, which DeepSeek accepts. Each such resume cost one extra round trip.

Now every assistant message sent to DeepSeek carries `reasoning_content`, `""` when it has none, so the first request is accepted. The same fix covers two rarer cases with the same refusal: a tool call whose reasoning came back empty, and turns from another provider after a switch. The fallback stays as a safety net. Other OpenAI-compatible servers never receive the field. Details: [docs/body/provider.md §3.8.1](../body/provider.md).

## Install

```sh
curl -fsSL https://github.com/nagisanzenin/INIT-Agent/releases/latest/download/get.sh | sh
init        # first run: pick a provider, paste a key (hidden), pick a model
```

In-place upgrade is not supported yet: the installer refuses when INIT is already installed. Run the current install's `uninstall.sh` first (it moves both homes to the Trash; nothing is deleted), then the line above.

## Verified for this release

On these exact bundles, at $0 on the mock model unless noted (full record: build/status/REL-033.md):

- **macOS fresh install** (a temp home with no Rust; get.sh installs Rust 1.97.1 with wasm32-wasip2 and clippy into it): installed and T2-capable in 70 s, first reply at 72 s.
- **macOS no-op T2 promote** on a fresh bundle install, with the shipped gate and the Rust get.sh installed: G0–G3 and the hot-swap handoff pass (G0 12.3 min including the cold build, G3 9.8 min, 23 min end to end, on a machine also running the CI below).
- **Linux fresh install** in a fresh Ubuntu 24.04 container (aarch64, Docker, no Rust preinstalled, bubblewrap 0.13.0): installed and T2-capable in 69 s, first reply at 70 s.
- **Pause and resume on both bundles, against the strict DeepSeek mock**: a turn is interrupted with SIGINT before the model's first token. The agent shows `paused · …` and goes idle. The next owner line resumes in exactly one request, accepted with no 400, which carries the paused turn as `[no visible output]` with `"reasoning_content": ""` and the `[init:paused]` note.
- **One live DeepSeek turn** through the macOS bundle: reply `ok` in 1.5 s, 1 request, 5,616 tokens in (4,992 cached), 2 out, $0.00022.
- On macOS, the CI steps for the changed code pass on the release commit: seed 351, kernel 882, TUI 101, extension 3, and the seed's own G0 and G1 (0 failed). The Root is unchanged since v0.3.1 except its version number; its suites were not rerun.
