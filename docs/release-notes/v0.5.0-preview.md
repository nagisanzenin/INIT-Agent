# INIT Agent v0.5.0-preview

*2026-10-28 · research preview · macOS (Apple silicon) and Linux x86_64 (experimental)*

Linux aarch64 has no 0.5.0 bundle yet: aarch64 machines stay on [v0.4.1-preview](v0.4.1-preview.md) until one is added to this release.

INIT is a harness in which a coding agent may rewrite itself, including its compiled core. It runs under a Root, a separate process the agent cannot change. The Root holds the keys, the sandbox and a signed record of every change, and it can always roll the agent back to its last known-good version.

This is a research preview, not a finished product. Everything in [v0.4.0-preview](v0.4.0-preview.md) and [v0.4.1-preview](v0.4.1-preview.md) still applies (goals with `/goal`, full access by default, how to confine it, the known limits), except where this page says otherwise.

## Upgrade in place: `init-agent upgrade`

Until now the only way to a new release was to uninstall and install again, which moved the agent's evolved body, its lineage and your keys to the Trash. From this release INIT upgrades in place and keeps what it has become: the body it evolved, its extensions, skills and sessions, the signed lineage, your keys and your charter.

```sh
init-agent upgrade                       # the latest release
init-agent upgrade --version 0.5.1       # a given release
init-agent upgrade --bundle FILE         # a downloaded bundle (its .sha256 next to it, or --sha256 HEX)
```

**From 0.4.1**, which has no `init-agent upgrade`, run this once from your own shell:

```sh
curl -fsSL https://github.com/nagisanzenin/INIT-Agent/releases/latest/download/get.sh | sh -s -- --upgrade
```

After that, `init-agent upgrade` works. The upgrade was tested from 0.4.1 only; for an older install the tested path is its `uninstall.sh` (which moves everything to the Trash), then a fresh install.

What the upgrade does, in order: it downloads the bundle and checks its SHA-256 into `~/.init-root/cache/upgrade/`, which the agent cannot write; stops the Root (a Root you started in a terminal is never signalled, so stop it with Ctrl-C first); refuses an older or the same release, and a release whose kernel cannot run your evolved body; snapshots what it replaces; installs the new Root, kernel and commands; starts a health probe (the kernel ready, your body booted, the lineage verified, within 120 s); then commits, or puts the old binaries back and returns the system to the tuple from before. Your evolved body is never migrated or rewritten. The details are in [docs/guide.md, Upgrade](../guide.md#upgrade).

Limits, plainly:

- **Bundles are checked by SHA-256 only; releases are not signed.** The checksum comes from the same GitHub release as the bundle, so it detects a broken download, not a compromised release.
- **The new seed is not merged.** A release's new prompts, skills and tools are not merged into the body INIT evolved; INIT keeps running its own body under the new Root and kernel.
- **No live swap.** INIT stops for the few seconds the upgrade takes.
- **An open self-change refuses the upgrade** (in `free` mode, a change group in its 2-72 h watch window must close first).
- **Only the no-service path was run end to end.** The upgrade's stop and start of the LaunchAgent or the systemd user unit use the same commands the installer and uninstaller already use, but no test drove them, because a test must not touch your running service.

## The installer asks one question

`install.sh` (which `get.sh` runs) no longer asks for a provider, a model or each limit. It prints the settings it writes into your charter and asks `Install with these settings? [Y/n]`; `get.sh` answers yes. Each setting has a flag (`--disk-floor`, `--day-usd`, `--total-usd`, `--max-level`, `--access full|workspace`). The provider, the model and the key are chosen on the first run of `init-agent`.

**Spending is tracked, not capped.** The day and total amounts in the charter ($5 and $25 by default) are what INIT shows its spend against; nothing stops INIT when they are reached. The one dollar limit the Root enforces is a goal's `usd=` budget, and it stops that goal, not INIT. Set a spending limit at your provider as well. The installer, the charter template and [the guide's Spending section](../guide.md#spending) now say this in those words.

**macOS: the `init` shim is gone.** v0.4.1 kept `~/.local/bin/init` on macOS as a shim that printed the new name. This release removes it, on install and on upgrade, the same way Linux removed the old launcher: only INIT's own `init` (checked by path, regular file and content), never another file named `init`. Use `init-agent`.

## Seeing what INIT does to itself

The TUI now shows each self-change as what it is:

- **A gate track.** While a change runs through the gate, one block shows its steps (G0 … G4, hand-off) with times. It ends as one line: `✓ kept`, `✕ refused at G2 … still on <parent>` (nothing went live), or `✕ rolled back at G4 … back on LKG` (it went live and was taken back).
- **A failed tool call shows why**: the last lines of its output under the call.
- **The lineage at the foot of Ctrl-O**: `verify ✓ N records · every signature`, or the first record that fails, and the newest records.
- **Colour means state.** Amber belongs only to the Root, cyan only to a change in flight, green only to something kept, red to harm and refusal. Four colour tiers (truecolor, 256, 16, `NO_COLOR`) with dark and light variants; `--theme light` for a terminal that does not report its background.
- **A liveness row** while the agent works (`waiting for the model · 12 s`, `thinking`, `writing · no new text for 9 s`, `running bash · 41 s`), and a status bar split between the agent (left) and the Root (right, ending in `root ok` or its alarm).
- **Pickers.** Setup, `/model` and `/key` use arrow-key pickers. The agent can ask you a question with 2-4 options through a new tool, `ask_owner`; the turn ends and your answer is your next message. Nothing is picked for you and there is no timeout. The question can never look like the Root: it is cleaned, capped, shown under the TUI's own label in plain colours, and an option that starts with `/` is sent quoted, never as a command. While it waits on you, a goal's wall clock is paused.

## Checking a published lineage offline

`init-root audit verify --file lineage.jsonl --pub <key> [--head <hash>]` checks a lineage file someone published, without an install: the hash chain, every Ed25519 signature from genesis, and key rotations. It proves that the records were not changed after they were signed; it does not prove that the binaries match the source. Publish the key and the head hash apart from the file. `scripts/proof/export.sh` prepares such a bundle from an install (sessions, the signed lineage and key, one diff per self-change, the spend ledger) and refuses if its scan finds a key or token.

## Other changes

- **On Linux the build disk floor read the sandbox's tmpfs; fixed.** The kernel checked free space before a self-change (`disk.min_free_build_gib`, 5 GiB) on its home directory, which inside its Linux sandbox is the sandbox's own tmpfs, not your disk. So on a machine with little RAM every promote was refused (`E_DISK`), and on others the check never saw the real disk. It now reads the bound build cache, which is on your disk. The Root's own disk floor (measured outside every sandbox) was never affected. macOS was not affected.
- **Fixes from the 2026-10-25 demo:** G0 no longer fails with a 63-64 byte `INIT_HOME`; a gate's G3 stops when the Root rolls its change group back; the body's boot message names the Root's rollback instead of a stale cause.
- **Anthropic and OpenAI cache writes are billed at their write prices.** The Root billed them at the input price, about 20 % under the provider's bill on a cold request. Now the ledger, the TUI's `$` and a goal's `usd=` meter use the charter's write prices; a model row without them is billed at twice the input price, so it can over-count, never under-count. DeepSeek is unchanged. A model you added with `providers add` before this release has no write prices: re-add it to get the catalog's.
- **Linux x86_64:** `get.sh` on a machine the release has no bundle for now names the platforms it has, instead of "download failed". `bundle.sh` checks that every binary matches its target triple.
- **Guide:** `/rollback settled|lkg|twin` returns the whole system to that tuple; a Spending FAQ.

## Live-tested and not

- **DeepSeek** (deepseek-flash, deepseek-v4-pro) is the only live-tested provider. This release made no live model call; everything below ran at $0 on the mock model (`init-mockllm`).
- **Anthropic and OpenAI** are not live-qualified. Their cache usage and billing are tested against recorded response shapes, and `scripts/qualify-provider.sh` (an owner-run live check inside a Root-metered budget of at most $10) is ready but has not run. `/model` shows which models are tested.
- **Linux x86_64**: on a GitHub-hosted Ubuntu 24.04 VM (x86_64, 4 vCPU), the bundle builds (the body inside the Linux build sandbox), passes the Linux sandbox checks and reproduces `self.json`; after INIT's AppArmor step it installs, answers, pauses and resumes, and a self-change of the compiled core (a no-op T2) passes G0–G3 and hands off, all on the mock model (G0 806 s, G1 1 s, G2 19 s, G3 789 s, hand-off 4.5 s). It has not run on physical x86_64 hardware or on a distribution other than Ubuntu 24.04.
- **Ubuntu 24.04** needs the one-time AppArmor step below.

## Linux: a one-time AppArmor step on Ubuntu 24.04

Ubuntu 24.04 restricts unprivileged user namespaces through AppArmor (`kernel.apparmor_restrict_unprivileged_userns = 1`, the default), and INIT's sandbox needs them: it starts util-linux `unshare`, then bubblewrap inside it. Ubuntu's own profiles do not cover that: we measured on a GitHub-hosted Ubuntu 24.04 VM that `bwrap-userns-restrict` and `unshare-userns-restrict` each let their program through, but bubblewrap started inside `unshare` is still refused.

So the installer now stops on such a system and prints these commands (`<gid>` is your group id; `scripts/install.sh --print-apparmor` prints them too):

```sh
sudo install -d -o root -g root -m 0755 /usr/local/lib/init-agent
sudo install -o root -g <gid> -m 0750 /usr/bin/unshare /usr/local/lib/init-agent/unshare
sudo install -o root -g <gid> -m 0750 /usr/bin/bwrap /usr/local/lib/init-agent/bwrap
printf '%s\n' 'abi <abi/4.0>,' 'include <tunables/global>' 'profile init-agent-unshare /usr/local/lib/init-agent/unshare flags=(unconfined) {' '  userns,' '}' 'profile init-agent-bwrap /usr/local/lib/init-agent/bwrap flags=(unconfined) {' '  userns,' '}' | sudo tee /etc/apparmor.d/init-agent >/dev/null
sudo apparmor_parser -r /etc/apparmor.d/init-agent
```

Run them once, then the installer again (or pass `--apparmor` to the installer, `curl … | sh -s -- -- --apparmor`: it asks, then runs them with sudo). They make root-owned copies of `unshare` and `bwrap` that only you can run, and load a profile that lets only those two copies create user namespaces; `/usr/bin/unshare`, `/usr/bin/bwrap` and every other program stay restricted. INIT starts its sandbox through the copies only if nobody but root can change them, and inside the sandbox nothing may create a namespace, as before. INIT does not ask you to lift the restriction for every program. Run the commands again after you update bubblewrap; `uninstall.sh` prints the commands that remove the copies and the profile. Details: [docs/platforms.md §3.4.6](../platforms.md).
