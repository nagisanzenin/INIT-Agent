# INIT Agent v0.3.1-preview

*2026-10-24 · research preview · macOS (Apple silicon) and Linux aarch64 (experimental)*

INIT is a harness in which a coding agent may rewrite itself, including its compiled core. It runs under a Root, a separate process the agent cannot change. The Root holds the keys, the sandbox and a signed record of every change, and it can always roll the agent back to its last known-good version.

This is a research preview, not a finished product.

## Full access by default

From this release the agent has **full access** by default ([ADR-012](../adr/012-full-access-by-default.md)): it reads, writes and runs anything you can and uses the network, like your own shell, so `~/Downloads` is your `~/Downloads`, and `git clone` or a package download just works. `FULL` shows in red in the status bar, and `init-root status` prints the access mode.

What stays off-limits, enforced by the OS sandbox (Seatbelt on macOS, bubblewrap and seccomp on Linux): the Root's home `~/.init-root` (your keys, the charter, the signed lineage, the snapshots, its sockets), the Root's service (`~/Library/LaunchAgents`, on Linux `~/.config/systemd/user`), INIT's launchers `init` and `init-tui`, the Root-written parts of `~/.init`, `~/.config/init-agent` and every path in your charter's `sandbox.read_deny`. The agent cannot signal the Root or start apps outside its sandbox. Fleet members and probes never get full access.

**What this means for you.** Anything the agent can read, `~/.ssh` and cloud credentials included, may be sent to the model provider or, in full access, anywhere on the network. `/undo` restores only the folder you started `init` in; changes elsewhere have no undo (the Root's rollback covers INIT itself, not your files). Files your own tools run later (shell startup files, `PATH` directories, editor configs, git hooks) are writable, so trust full access like your own shell.

**How to confine it.** Workspace mode is v0.3.0's behaviour, unchanged: reads of your home minus secrets, writes only in the start folder and `~/.init`, no network except the model provider.
- For one session: `init --workspace`, or `/full off` in the chat (`/full on` lifts it again). `WORKSPACE` shows in yellow.
- Always: set `mode = "workspace"` under `[sandbox]` in `~/.init-root/charter.toml`, then `init-root charter check --apply`. `/full on` then asks you to type a confirmation.
- Never full: `allow_full = false` under `[sandbox]`.

On Linux, full access works as on macOS; workspace mode there keeps the agent in its own home (it cannot read or edit your files), as in v0.3.0.

## Install

```sh
curl -fsSL https://github.com/nagisanzenin/INIT-Agent/releases/latest/download/get.sh | sh
init        # first run: pick a provider, paste a key (hidden), pick a model
```

get.sh picks the bundle for your machine, checks its sha256, unpacks it into `~/.local/share/init/<version>/`, installs the Rust toolchain INIT rebuilds itself with (rustup 1.97.1 with wasm32-wasip2 and clippy; your shell files and default toolchain are left alone; `--no-rust` skips it), then runs the bundle's installer, which states the access default and the three ways to confine it. Nothing needs sudo.

## Also new

- The TUI's `--workspace` flag (it excludes `--full`), a `FULL`/`WORKSPACE` badge that is never dropped on a narrow terminal, and new `/full` help.
- A full grant sets the agent's `HOME` to yours, drops `CARGO_NET_OFFLINE` and adds `~/.local/bin` and `~/.cargo/bin` to its `PATH`. The agent's own git sync ignores your `~/.gitconfig`.
- Linux: the full layout pins every ancestor of a protected path, so renaming `~/.local/bin` or `~/.config/systemd` away to plant a replacement fails (EBUSY); `systemctl --user` cannot reach the Root's unit.

## Before you install

- **Spending is not capped by INIT.** It meters and shows estimated cost (`/usage`, the status bar) but never stops at a dollar amount. Stop it with `/stop` or `/panic`, and set a spend limit at your provider.
- **Autonomy is capped at L0** (its whole body may change; its kernel may not).
- **Known residuals of full access** (ADR-012): `launchctl remove dev.init.root` from inside any sandbox stops the Root and every agent process (it ends INIT, it does not escape it; log in again or `launchctl bootstrap` the plist); on Linux, abstract Unix sockets and the system D-Bus stay reachable.
- **Linux is experimental.** aarch64 only, tested in Docker (Debian 12, Ubuntu 24.04) on the mock model. It needs bubblewrap ≥ 0.13 at `/usr/bin/bwrap`; no LTS distro ships it, so build it from the upstream release (docs/platforms.md §3.4.0). x86_64 compiles but is untested. Windows is unsupported.
- **DeepSeek is the only provider used live.** OpenAI-compatible gateways, OpenAI Responses, Anthropic Messages and local servers are experimental.
- There is still no evidence that self-evolution improves results on today's models; see the [technical report](../../reports/INIT%20technical%20report.md).

## Verified for this release

On these exact bundles, at $0 on the mock model unless noted (full record: build/status/FULLACCESS.md, "Release"):

- **macOS fresh install** (a temp home with no Rust; get.sh installs Rust 1.97.1 with wasm32-wasip2 and clippy into it): installed and T2-capable in 42 s, first reply at 45 s. `init-root status` says `access: FULL (default)`, and the agent's boot block says so too.
- **macOS no-op T2 promote** on that fresh bundle install, with the shipped gate and the Rust get.sh installed: G0–G3 and the hot-swap handoff pass (G0 10 min including the cold build, G3 7 min, 17 min end to end).
- **Linux fresh install** in a fresh Ubuntu 24.04 container (aarch64, Docker, no Rust preinstalled, bubblewrap 0.13.0): installed and T2-capable in 55 s, first reply at 56 s, access FULL by default.
- **One live DeepSeek turn** through the macOS bundle (first-run setup in the TUI, key typed into the hidden field): reply in 2.2 s, 1 request, about $0.0005.
- On macOS, 1,897 CI tests pass on the release code (0 failed); on Linux, the sandbox and Root suites pass, including a real-isolation test of the full-access layout.
