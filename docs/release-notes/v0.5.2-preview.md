# INIT Agent v0.5.2-preview

*2026-10-29 · research preview · a readiness patch · macOS (Apple silicon) and Linux x86_64 (experimental)*

v0.5.2 fixes what a first-time user ran into on v0.5.1, and what the review after the v0.5.1 release found. In the
v0.5.1 user session, an agent playing a new user said "do not ship". On this release, both the new-user and the
returning-user sessions said **ship**. Everything in
[v0.5.1-preview](https://github.com/nagisanzenin/INIT-Agent/blob/main/docs/release-notes/v0.5.1-preview.md) still
applies, except where this page says otherwise. Linux aarch64 still has no 0.5.x bundle.

## Upgrade

From 0.5.1: `~/.local/bin/init-agent upgrade`. From 0.5.0 or 0.4.1, run this once from your own shell:

```sh
/usr/bin/curl -q -fsSL https://github.com/nagisanzenin/INIT-Agent/releases/latest/download/get.sh | /bin/sh -s -- --upgrade
```

If you installed with `INIT_ROOT_HOME` set, put `INIT_ROOT_HOME=<that directory>` before `/bin/sh`; get.sh prints the
line with it filled in. See
[Install, upgrade, uninstall](https://github.com/nagisanzenin/INIT-Agent/blob/main/docs/guide.md#install-upgrade-uninstall).

## A self-change is no longer refused at random on a busy machine

Three of the body's tests depended on timing:
- one expected a helper script to start within 2 seconds;
- one read a test server's file before the server had finished writing it;
- one, used by developers, waited a fixed 30 seconds.

On a loaded machine they failed often enough to refuse good self-changes: 3 of 5 macOS runs on release day. All three
are fixed at the cause. The test server now writes its files atomically, and the waits are tied to events, not clocks.
Every timing assertion in the body's tests was reviewed. The body's whole suite then passed 10 times out of 10 while 8
processes kept every core busy. The macOS self-change of the compiled core passed through all four gates and the
hand-off on this release.

## What a new user hit, fixed

- **The first self-change of the core** builds its dependencies cold. On an M2 that took 17 and 21 minutes in the
  v0.5.1 and v0.5.2 new-user sessions, which ran beside a release job, and in v0.5.0's release check the whole of G0, dependencies
  included, took 430 s (docs/guide.md, "Time"). That build is now its own step on the gate track, with an estimate of
  10–20 minutes. It is no longer shown as "waited".
- **`/undo` after you reopen INIT** goes back to before the agent's edits. It restores the newest snapshot that
  differs from your folder. `/undo list` shows the snapshots, and `/undo <id>` picks one. A launch where nothing
  changed no longer takes a snapshot.
- **An unknown command** such as `/undo lst` is refused in the TUI instead of being sent to the model and billed.
  `/help` lists the commands. Start a line with `//` to send it to the model as text.
- **After `/panic` and `/resume`**, the footer shows the version that really runs. Before you confirm, `/panic` says
  which kept changes a resume would drop.
- **Money:** a turn replayed after a relaunch shows `$?`, never `$0.000`. "incl. checks" appears only when a gate ran.
- **`/details` and Ctrl-O** show the whole call and the last lines of a command's output, successful or not.
- **The README's install lines** work on a fresh Mac: no `#` comment, which zsh passed as an argument, and the first
  run is `~/.local/bin/init-agent`. The installer prints that full path, and how to put it on your `PATH`.

## Upgrades and installs, after the v0.5.1 review

- **The Root never runs the agent while an upgrade is half done.** This could happen after a reboot in the middle of an
  upgrade. If the commit had begun, the Root finishes it. Otherwise it rolls the upgrade back and the service starts
  the old Root.
- `upgrade --commit` run by hand now also installs the new release's get.sh, so `init-agent upgrade` never keeps an
  old one.
- **A second install by mistake is refused.** If INIT lives in another `INIT_ROOT_HOME`, get.sh and install.sh refuse
  a fresh install and print that home's upgrade line.
- On a machine with no bundle for this release (Linux aarch64), get.sh no longer advises an upgrade that cannot work.
- The uninstaller honours a custom `INIT_BIN_DIR`, and its printed command carries `INIT_ROOT_HOME`.

## Known limits

- **`/undo` can lose files if your folder holds a read-only directory** (for example a vendored module cache). It removes the folder's entries before it copies the snapshot back, and a read-only directory stops it halfway. This is not new in 0.5.2, and the fix is planned for v0.5.3. Until then, make such directories writable before `/undo`, or copy files back by hand from `~/.init-root/snapshots/<id>/`.
- Some messages still print a bare `init-agent upgrade` or `init-agent --workspace`. On a fresh Mac, use `~/.local/bin/init-agent …`, or add `~/.local/bin` to your `PATH`. On Linux, the installer's PATH hint names `~/.zshrc`; bash users add it to `~/.bashrc`.
- **The `deps` step has no estimate of what is left once it starts.** The kernel reports the start of the dependency
  build, not its end, so the panel learns it only when G0 finishes.
- **`/usage` can show a self-change's checks at two prices**, before and after a relaunch: the Root's charter has one
  DeepSeek price, and the kernel's config has an off-peak price. Both are labelled as estimates. This will be
  reconciled in v0.5.3.
- **After an upgrade the conversation screen starts empty.** The session is kept, and the model still gets it. The
  Root's replay buffer is in memory, so a restart clears it.
- **An upgraded install keeps the body it evolved.** It does not get this release's body changes: the fuller
  `/details` output and the test fixes. The upgrade does not yet offer a release's new seed.
- A few messages still print a bare `init-agent` (the quit line, the Root's terminal window).
- In developer CI, the sealed judge's determinism test once recorded a run's exit code as missing under heavy load.
  It passed alone. It is under investigation for v0.5.3.
- Anthropic and OpenAI are not live-qualified. Releases are checked by SHA-256 and not yet signed; signing is planned
  for v0.5.3.

## Verified for this release

Everything below ran at $0 on the mock model. The full record is
[REL-052](https://github.com/nagisanzenin/INIT-Agent/blob/main/build/status/REL-052.md).

- **macOS arm64 bundle:**
  - install and first reply, Esc pause and resume, and the source install all pass;
  - **a self-change of the compiled core through G0–G3 and the hand-off passes** (G0 975 s, G3 822 s, hand-off 6.3 s,
    beside a CI run);
  - **upgrade from an evolved 0.5.1** passes: the install kept a self-made tool through the gates, and the upgrade
    kept it, with the lineage, keys and sessions. A broken bundle rolled back, and an incompatible one was refused.
- **Install matrix:** the installer was run on a clean home and on installs of 0.3.1, 0.3.2, 0.3.3, 0.4.0, 0.4.1,
  0.5.0 and 0.5.1, 8/8 PASS.
- **Linux x86_64 bundle** (a hosted Ubuntu 24.04 VM): install and first reply, pause, and a self-change of the core
  through G0–G3 and the hand-off, all pass.
- **The body's test suite** passed 10/10 runs while 8 processes kept every core busy.
- **CI on macOS:** 2,108 Rust tests passed. One developer-only kernel test failed once under load and passed alone
  (see Known limits).
- **Two agent-run user sessions said ship:** a new user on a clean Mac, and a returning user upgrading from 0.5.1.
  Every v0.5.1 blocker was checked as fixed.

## Not verified

- An upgrade on Linux x86_64: the matrix and the upgrade check ran on macOS.
- The upgrade's LaunchAgent path on this release. It was first run for real on the owner's Mac with 0.5.1.
- Linux aarch64 (no 0.5.x bundle), Anthropic and OpenAI on a live API, and any live model call in this release.
