# INIT Agent v0.4.0-preview

*2026-10-26 · research preview · macOS (Apple silicon) and Linux aarch64 (experimental)*

INIT is a harness in which a coding agent may rewrite itself, including its compiled core. It runs under a Root, a separate process the agent cannot change. The Root holds the keys, the sandbox and a signed record of every change, and it can always roll the agent back to its last known-good version.

This is a research preview, not a finished product. Everything in [v0.3.3-preview](v0.3.3-preview.md) and the releases before it still applies (Esc and Ctrl-C pause, full access by default, how to confine it, the known limits).

## Goals: `/goal` (GBAL, [ADR-013](../adr/013-goal-based-agentic-loop.md))

Until now INIT changed itself when it hit friction. v0.4 lets you give it a direction:

```
/goal "answer short questions about this folder with fewer model requests per turn" done=card:requests_turn<=2 usd=0.40 wall=3h rounds=8 guard=cost_turn:300,provider_errors
```

Only you can set a goal (the agent may propose one, which you adopt with `/goal adopt <id>`). The agent then works in rounds: it reads a noise floor, commits a change to its own Body, files a prediction (which card, which direction, how sure), and promotes the change. The Root, which the agent cannot change, keeps the books:

- **Cards.** Six observation cards computed from what the Root already meters on your turns: cost, wall time and model requests per turn, cache reads, provider errors, and your corrections. A reading compares the change's first turns with the turns before it: mean, σ, the standard error of the difference, z, and a verdict (`better`, `worse`, `noise`).
- **Registered predictions.** A reading counts for the agent only if its prediction was filed before the change went live. The forecasts are scored (Brier), and the score sets one thing: how many rounds the agent may run before it checks in with you (3 by default, 1 to 12). It never touches the autonomy ladder or your budget.
- **Guardrails.** A `guard=` card that gets worse beyond your tolerance rolls the change back, and only that change.
- **The budget is yours** (`usd`, `wall`, `rounds`). The Root charges the goal every metered request while it is active and stops the goal at its budget.
- **`met` must be earned.** For a card goal the Root checks the agent's `met`: the card must have reached your threshold *and* a registered change must have moved it beyond noise in the predicted direction. Otherwise it records `met_unattributed` and tells you.

The loop itself (how to choose a mode, when to keep a change, when to stop) lives in two skills the agent may rewrite, `gbal` and `goal-loop`. The user guide has the details: [docs/guide.md, Goals](../guide.md#goals-goal-v04).

### What the real-model runs showed

We ran GBAL four times on deepseek-flash in an isolated install, free mode, workspace access, with the goal above (records: build/status/GBAL-REAL.md). Spend is the Root's estimate, not an invoice.

- **First run ($0.065): the chain worked once, and found six bugs.** The agent's first change (a "turn economy" block in its prompt) took requests per turn from 2.6 to 1.0, but its prediction named a commit it then amended, so the reading was unregistered and counted for nothing. A deliberately bad second change was predicted in time; it broke the 30 % cost guardrail and the Root vetoed it. But the kernel did not apply that rollback for 2 minutes (G2), and the agent's own rollback then went all the way back to genesis and dropped the good change too. The outcome scored the forecast regression as a miss (G4). Repeat questions in the same session also inflated the 2.6 → 1.0.
- **Rerun A ($0.076): not passed.** The kernel's commit rules refused the promote *after* each prediction (prose in `Repro:`, an unknown subject type). Each amend made the prediction stale, each re-file spent one of the owner's rounds, and `rounds=3` ran out before anything went live (G7). The bad change was rolled back to its parent in 3.9 s (the G2 fix held).
- **Rerun B ($0.053): round 1 only.** Round 1 was registered: requests 2.4 → 2.0, z +1.64, noise, scored o = 0. Round 2's prediction was refused because the re-files had used up the check-in interval, and the agent promoted anyway, so round 2 was unregistered.
- **Rerun C ($0.060): the full chain.** Round 1 (after two amends and three filings) was registered: 2.4 → 2.0, noise, o = 0. After the owner's check-in, round 2, the deliberate regression, was predicted `worse` at p 0.9, read worse (cost +137 %, z −14.7), rolled back by the guardrail to its parent in 3.8 s with the good change kept, and scored as a hit (o = 1). Brier 0.106 over n = 2.

What we take from this: the Root's record, guardrails and rollback work on a real model. The two goal changes that were registered read as noise. Two that read better were not registered: the first run's (z +6.6, inflated by repeat questions) and run A's (2.2 → 1.2 requests per turn on new questions, z +3.5, predicted on a stale commit). So the runs show the instrument, not a gain. They also found the bugs below. In B and C the agent stopped as `met` on a reading that was noise. Under v0.4's rule that is `met_unattributed`.

### Fixed after those runs (all tested at $0; not yet rerun on a real model)

- **G7: re-files no longer spend your rounds.** `initctl promote --check evo/<id>` runs promote's commit checks (subject, trailers, the exact `Repro:` forms) and promotes nothing; the `gbal` skill runs it before every prediction. A re-file that replaces the agent's newest prediction while its change has never gone live keeps the same round and check-in step, and the old prediction closes as `superseded`.
- **`met` requires attribution**, as above.
- **The goal's meter equals the egress ledger.** It used to add each closed turn's cost and missed the turn in which the agent stopped the goal (run C: 51,290 against the ledger's 59,718 µUSD). It now charges every request at settlement, and the $0 end-to-end test checks the two agree to the µUSD.
- **G2:** a guardrail rollback of a free-path change whose parent is not the kernel's last known-good is applied at once, to the parent (3.8–4.2 s in the reruns), and `initctl rollback` undoes only the change group of the running version.
- **G4:** an outcome scores what was forecast, on the prediction's own card. A regression the agent predicted and your guardrail caught is a hit, not a miss.
- **G1, G3, G5, G6:** an owner turn closes when the agent goes idle (lines 2 s apart were one turn and the cards saw nothing); a prediction for a change already live is refused with the reason; `Predicts:` accepts `card:<id>`; the skill says to predict on the final commit, before promote.

## Fixes found in the real-model demo of 2026-10-25

- **A fresh gated install rolled back every T1/T2 change** about 1.3 s after its swap: with no sealed tasks and an empty pool, the G4 gate had nothing to measure, read that as inconclusive, and the incumbent won. No instrument is now no G4 evidence: the change is kept on G0–G3 (as a T0 change is), with a `g4_no_instrument` alert.
- **An owner `/rollback` quarantined GENESIS.md, SELF.md and four seed skills.** The seed's own files are now a baseline that no change group owns, so a rollback never quarantines them.
- **Switching `extend.mode` while INIT ran was not picked up**: the next handoff was refused and the whole system restarted. The Root now pushes the new mode to the running kernel. An incident at L0 is recorded as a floor, not as a demotion.
- **Gate notices said only `[kernel] gate`.** They now say which stage, the verdict, the commit, the reason and what happens next.
- **An owner line's acknowledgement could arrive before the line was registered**, so the line counted as unanswered; two in a row could restart the kernel or roll back every open change. The acknowledgement is now kept until its line arrives.
- The user guide documents `/rollback`, `/goal`, and that the free path needs the disk floor plus 2 GiB.

## Limits

- **No gain is shown yet.** GBAL measures whether a self-change helps. In the runs above no registered change helped beyond noise; the one clean-looking gain (run A, z +3.5) was unregistered, from one run. The value so far is the honest record, not a result.
- Cards read your turns, so a reading takes `n` turns (5 by default) on each side. At a few turns a day that is slow.
- An agent can lower `cost_turn` by doing less. Use `corrections` as a guardrail.
- Only the card goals (`done=card:…`) are checked by the Root. `exemplar` and `owner` goals are judged by you (`/goal accept|reject`). Task cards and artifact capture (ADR-013 phase 2 and 3) are not built.
- One goal is active at a time.
- Autonomy is still capped at L0; DeepSeek is the only provider tested live; Linux is aarch64 only and experimental.

## Install

```sh
curl -fsSL https://github.com/nagisanzenin/INIT-Agent/releases/latest/download/get.sh | sh
init        # first run: pick a provider, paste a key (hidden), pick a model
```

In-place upgrade is not supported yet: the installer refuses when INIT is already installed. Run the current install's `uninstall.sh` first (it moves both homes to the Trash; nothing is deleted), then the line above.
