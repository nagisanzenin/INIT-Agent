# INIT Agent v0.5.1-preview

*2026-10-28 · research preview · a security and readiness patch · macOS (Apple silicon) and Linux x86_64 (experimental)*

v0.5.1 fixes what an independent review of the shipped v0.5.0 and two user sessions found, on the day v0.5.0 shipped.
Two of the fixes close ways around the Root. Update if you run INIT in workspace mode, or if you ever upgrade from a
bundle file. Everything in [v0.5.0-preview](https://github.com/nagisanzenin/INIT-Agent/blob/main/docs/release-notes/v0.5.0-preview.md) still applies, except where this page says otherwise.
Linux aarch64 still has no 0.5.x bundle.

## Upgrade

From 0.5.0 or 0.4.1, run this once from your own shell:

```sh
/usr/bin/curl -q -fsSL https://github.com/nagisanzenin/INIT-Agent/releases/latest/download/get.sh | /bin/sh -s -- --upgrade
```

This runs 0.5.1's get.sh with the system's curl and sh. 0.5.0's own `init-agent upgrade` would run 0.5.0's get.sh,
which has the problems listed under "Security fixes", and its `--version 0.5.1` asks for a tag that does not exist. If you installed with `INIT_ROOT_HOME` set, put `INIT_ROOT_HOME=<that directory>` before `/bin/sh`; get.sh prints the line with it filled in. From
0.5.1 on, `init-agent upgrade` is enough. For an install older than 0.4.1, uninstall first; get.sh prints the
command. See [Install, upgrade, uninstall](https://github.com/nagisanzenin/INIT-Agent/blob/main/docs/guide.md#install-upgrade-uninstall).

## Security fixes

**Workspace mode: an agent could redirect git's config in your folder** (macOS).
- In workspace mode the agent may write the folder you started INIT in. The sandbox denied writes to `.git/config`
  and `.git/hooks`, but git reads its config and commands from other places too.
- By writing `.git/commondir`, renaming `.git` aside, creating a `.git` file, or renaming a directory onto
  `.git/modules/<m>`, an agent acting against you could point git at a config it wrote. Your next `git status` in
  that repository would then run its command, outside the sandbox, with your rights.
- The sandbox now denies the `.git` entry itself and every config and command source git reads, in `.git/`,
  `.git/modules/…` and `.git/worktrees/…`, including renames onto them. Committing still works.
- In workspace mode the agent can no longer `git init`, add a submodule or add a worktree in your folder.
- Linux was not affected: there, workspace mode keeps the agent in its own home.
- In full access, the default, nothing changes. The agent can write what you can, except the Root, as
  [ADR-012](https://github.com/nagisanzenin/INIT-Agent/blob/main/docs/adr/012-full-access-by-default.md) has always said.

**Upgrading from a bundle file trusted files the agent could write.**
- `init-agent upgrade --bundle FILE` checked the bundle where it lay, then unpacked it from the same place. It took
  the expected SHA-256 from a `.sha256` file beside it. With full access, the agent can write both.
- Now the bundle is copied into `~/.init-root/cache/upgrade/` first, and only that copy is checked and unpacked.
  A bundle file needs `--sha256` on the command line; without it, the upgrade stops and prints the exact command.
- An upgrade from a release bundle (the usual case) now runs only the system's tools (`PATH=/usr/bin:/bin:/usr/sbin:/sbin`), from `/`, with curl ignoring `~/.curlrc`. An upgrade from a source checkout still uses your `PATH`, because it builds with your cargo.
  The Root's own git calls ignore the repository you start them in.
- `--version 0.5.0` now finds the tag `v0.5.0-preview`.

No exploit of either hole was seen. The post-release review found both.

## Upgrades

**After an upgrade, a panic could bring back the old kernel.**
- `upgrade --commit` moved the last-known-good pointer to the new version, but left the rollback anchors on the
  version from before.
- After `/panic` and `/resume`, the Root reinstalled the old `init-kernel` and ran it under the new Root.
- The commit now moves every anchor to the new kernel, keeping the body your INIT evolved. An anchor it cannot read
  is cleared and reported, never kept silently.
- An install upgraded to 0.5.0 keeps its old anchor until this upgrade moves it.

## What the user sessions found

Two agents played a new user and a returning user on v0.5.0, through the real TUI. Both said "do not ship". The
fixes:
- **`/` then Tab completed to `/panic`, and it ran at once.** Safe commands now come first. In the TUI, `/panic` says
  what it does and runs only after you type `panic` (or `/panic` again); nothing the agent sends can cancel that step.
  Line mode (`init-agent --raw`, for scripts) still panics at once.
- **Commands we printed did not run.** The Root and the TUI told you to run `init-root …`, which is not on your
  `PATH`. Every command INIT prints now runs as printed: `~/.init-root/bin/init-root …`, or an `init-agent` form. A
  test checks the Root's messages, the installer's and the TUI's.
- **Refusals say the rule and the fix.** That covers a workspace outside your home, an agent that cannot start, and a
  Root started from the wrong HOME. Without a workspace, the screen says the agent works in `~/.init/work` and `/undo`
  has nothing to restore.
- **Numbers agree.** `/usage` no longer shows "$0.00" for a self-change's checks when the Root metered them. Every
  amount uses one rounding rule. A turn's cost stops at the end of its run. The gate rows add up to the total. An
  unscored G4 says "not scored". The dollar amounts in `/root status` are labelled as records, not caps.
- **An answered question stays answered** after you reopen the TUI.
- **Quitting** with Ctrl-D leaves no half-drawn box. It says the agent keeps running and how to come back.

## Documentation

- The README now says what INIT is, how it works, what it has done and its limits, in half the length. Install and
  upgrade details moved to the [guide](https://github.com/nagisanzenin/INIT-Agent/blob/main/docs/guide.md#install-upgrade-uninstall).
- [docs/foundations.md](https://github.com/nagisanzenin/INIT-Agent/blob/main/docs/foundations.md) is the formal model INIT's guarantees are stated against. It defines two
  guarantees (recoverability, and Root-only evidence), twelve invariants with their status, the assumptions, and
  what INIT does not promise.
- [docs/release-protocol.md](https://github.com/nagisanzenin/INIT-Agent/blob/main/docs/release-protocol.md): every release now passes the same gates. These include
  `scripts/install-matrix.sh` (the installer on a clean machine and on every public release since 0.3.1), two
  agent-run user sessions, and an independent review after release.
- Corrected numbers:
  - README said a small core change takes "about 2 min end to end". That was never measured. The README now gives what
    was: 788 s (13.1 min) from G0 to the hot-swap, built cold (v0.5.0, M2, mock model), and 126 s for build and G0
    when warm.
  - ADR-011's harm-signal parameters and ADR-013's guardrail false-alarm rate (2.3 %; about 5.1 % in practice) now
    carry notes where the code differs. The guardrail fix is planned for v0.5.2.

## Known limits

- **The genesis fallback.** If, after an upgrade, the last-known-good, settled and audited versions all fail to
  verify, a resume falls back to the genesis tuple, which holds the install's original kernel. This is the last
  resort, and it is scheduled for v0.5.2.
- **Releases are checked by SHA-256 only, not signed.** Signing with an offline key is planned for v0.5.2.
- Anthropic and OpenAI are not live-qualified. DeepSeek is the only live-tested provider.
- Two things the user sessions raised are not changed in this release: the gate track shows no estimate of how long a
  self-change will take, and some status labels read "live" when the model is the mock.

- **On a busy machine, two flaky body tests can refuse a good self-change of the compiled core.** This is not new in
  0.5.1. One expects a helper script to start within 2 seconds. The other reads a test server's file before the server
  has finished writing it. Either can fail the build-and-test check (G0, or G0 inside G3), and then the change is
  refused. On this release's test machine they failed 3 of 5 self-change runs while other builds ran beside them. They
  passed on the hosted x86_64 runner and whenever the machine was otherwise idle. Nothing unsafe is admitted: retry
  the change when the machine is quieter. Fixing both, with an audit of every such timing assertion, is the first item
  of v0.5.2. Another test of this kind, found on the x86_64 runner, is fixed in 0.5.1.

- **What a new user still runs into.** An agent-run session with a first-time user, on this release, said "do not
  ship". The owner shipped 0.5.1 anyway, because it closes two holes in 0.5.0 and makes none of these worse. The
  readiness patch before the Show HN fixes them:
  - the first self-change of the compiled core shows its cold dependency build (about 17 minutes) as "waited", with no
    estimate of how long is left;
  - `/panic` then `/resume` returns to the last audited version, which on a fresh install is the original one, so a
    change you just kept is dropped (the confirmation says so, but the footer keeps showing the dropped version);
  - `/undo` restores the newest snapshot, and every launch takes one, so after you reopen INIT it cannot go back to
    before the agent's edits;
  - an unknown command such as `/undo list` is sent to the model as a message, and billed;
  - a replayed turn's cost shows `$0.000`;
  - `/details` does not show a successful command's output.

## Verified for this release

Everything below ran at $0 on the mock model. The full record is
[REL-051](https://github.com/nagisanzenin/INIT-Agent/blob/main/build/status/REL-051.md).

- **macOS arm64 bundle:**
  - install and first reply (bundle-e2e) PASS, and the same on the bundle downloaded from this page;
  - Esc pause and resume PASS;
  - source install (release-e2e) PASS;
  - **upgrade from an evolved 0.5.0** PASS: the 0.5.0 install kept a self-made tool through the gates, and the
    upgrade kept it, along with the lineage, keys and sessions. A broken bundle rolled back, and an incompatible
    one was refused.
- **Install matrix:** the installer was run on a clean home and on installs of 0.3.1, 0.3.2, 0.3.3, 0.4.0, 0.4.1
  and 0.5.0, 7/7 PASS. The older releases got the uninstall line; 0.4.1 and 0.5.0 were upgraded to 0.5.1.
- **Linux x86_64 bundle** (a hosted Ubuntu 24.04 VM): install and first reply, pause, and a self-change of the
  compiled core through G0–G3 and the hand-off, all PASS.
- **The owner's own Mac** was upgraded 0.5.0 → 0.5.1 with the command at the top of this page. The LaunchAgent
  stopped and started, the rollback anchors moved, and the lineage verified.
- **CI on macOS:** 2,082 Rust tests passed. One developer-only test failed under a load average of 76 and passed
  alone. The body's test suite passed 5 more times while the machine was loaded.
- **Reviews:**
  - two independent reviews before the release, whose findings are all fixed with tests;
  - two agent-run user sessions: the returning user said ship, the new user said do not ship, with the blockers
    listed above.

## Not verified

- **The macOS self-change of the compiled core on this bundle.** The first attempt lost G0, and the second (with
  G0–G2 passing) lost G3's inner G0, each to one of the two flaky tests above. The same change passed on Linux x86_64, and on the v0.5.0 bundle.
- **An upgrade on Linux x86_64.** The matrix and the upgrade check ran on macOS only.
- Linux aarch64 (no 0.5.x bundle), Anthropic and OpenAI on a live API, and any live model call in this release.
