# INIT Agent v0.3.2-preview

*2026-10-25 · research preview · macOS (Apple silicon) and Linux aarch64 (experimental)*

INIT is a harness in which a coding agent may rewrite itself, including its compiled core. It runs under a Root, a separate process the agent cannot change. The Root holds the keys, the sandbox and a signed record of every change, and it can always roll the agent back to its last known-good version.

This is a research preview, not a finished product. Everything in [v0.3.1-preview](v0.3.1-preview.md) still applies (full access by default, how to confine it, the known limits).

## Esc and Ctrl-C now pause

Before this release, Esc or Ctrl-C while the agent worked ended the task. If the interrupt landed before the model's first token, the turn ended with an empty reply, and the agent read your next message as a new request.

Now an interrupt from you is a **pause**:

- The agent stops at once, as before. Work it finished stands; tool calls it had not started yet are marked `aborted: not executed` and did not run.
- The status line says `paused · type to continue, or say what to do instead`.
- Your next message continues the task where it stopped (the agent re-issues only the calls that did not run and says so in one line), unless that message changes or drops the task.
- Esc with a steer still in the pending tray keeps its v0.3.0 meaning: interrupt, then continue at once with your note.
- `stop`, end of input (EOF) and faults still abort the run, show `aborted` and add no pause note.

How it works: the body records that the abort came from the owner, and the run's final boundary appends one harness message (`[init:paused] …`) after the tool results. The message is appended once and never rewritten, so the prompt cache is unaffected. Details: [docs/body/loop.md §3.5.1](../body/loop.md).

## Install

```sh
curl -fsSL https://github.com/nagisanzenin/INIT-Agent/releases/latest/download/get.sh | sh
init        # first run: pick a provider, paste a key (hidden), pick a model
```

In-place upgrade is not supported yet: the installer refuses when INIT is already installed. Run the current install's `uninstall.sh` first (it moves both homes to the Trash; nothing is deleted), then the line above.

## Verified for this release

On these exact bundles, at $0 on the mock model unless noted (full record: build/status/REL-032.md):

- **macOS fresh install** (a temp home with no Rust; get.sh installs Rust 1.97.1 with wasm32-wasip2 and clippy into it): installed and T2-capable in 48 s, first reply at 51 s.
- **macOS no-op T2 promote** on a fresh bundle install, with the shipped gate and the Rust get.sh installed: G0–G3 and the hot-swap handoff pass (G0 7.3 min including the cold build, G3 5.4 min, 13 min end to end).
- **Linux fresh install** in a fresh Ubuntu 24.04 container (aarch64, Docker, no Rust preinstalled, bubblewrap 0.13.0): installed and T2-capable in 41 s, first reply at 42 s.
- **The pause, on both bundles** (macOS and the Ubuntu container): a turn is interrupted with SIGINT while the model stream is stalled; the agent shows `paused · …` (not `aborted`) and goes idle; the next owner line resumes, and that model request carries the `[init:paused]` note, which the first request did not.
- **One live DeepSeek turn** through the macOS bundle (first-run setup in the TUI, key typed into the hidden field): reply `ok` in 1.1 s, 1 request, about $0.0005.
- On macOS, the CI steps for the changed code pass on the release commit: seed 350, kernel 882, TUI 101, extension 3, and the seed's own G0 and G1 (0 failed). The Root is unchanged since v0.3.1 except its version number; its suites were not rerun.
