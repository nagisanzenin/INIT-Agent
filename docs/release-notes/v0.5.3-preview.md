# INIT Agent v0.5.3-preview

*2026-10-29 · research preview · macOS (Apple silicon) and Linux x86_64 (experimental)*

v0.5.3 fixes what the review after v0.5.2 found, closes the Root's known invariant gaps, makes INIT's statistics hold
the error rates they state, signs releases, and makes the meter honest about what it does not know. Everything in
[v0.5.2-preview](https://github.com/nagisanzenin/INIT-Agent/blob/main/docs/release-notes/v0.5.2-preview.md) still
applies, except where this page says otherwise. Linux aarch64 still has no 0.5.x bundle.

## Upgrade

- **From 0.5.1 or 0.5.2:** `env -i HOME="$HOME" ~/.local/bin/init-agent upgrade`. The `env -i` matters: in full
  access, an agent could have planted `INIT_DIST_URL` in your shell's startup file, and 0.5.1/0.5.2's upgrade would
  follow it. From 0.5.3 on, releases are signed and an upgrade checks the signature against the key your installed
  Root pins, so a planted URL can no longer choose what you install. A planted `INIT_ROOT_HOME` still can until
  v0.5.4 (0.5.3's `init-agent upgrade` prefers it to its own home), so use the same line for upgrades from 0.5.3 too.
  If you run the Root in a terminal of its own instead of as a service, stop it there first (Ctrl-C); the upgrade
  refuses until you do, changes nothing, and prints the line that starts it again afterwards.
- **From 0.5.0 or 0.4.1,** once, from your own shell:
  ```sh
  /usr/bin/curl -q -fsSL https://github.com/nagisanzenin/INIT-Agent/releases/latest/download/get.sh | /bin/sh -s -- --upgrade
  ```
  With a custom `INIT_ROOT_HOME`, put `INIT_ROOT_HOME=<that directory>` before `/bin/sh`; get.sh prints the line
  filled in.
- **Before 0.4.1:** uninstall with the line get.sh prints, then install fresh.

The release key's fingerprint is `SHA256:IS7wIWkppZkHSUwdnsJR+K4fBPkmPa/IJwfNi9sIoMs`. To check a download by
hand, see [Release signing](https://github.com/nagisanzenin/INIT-Agent/blob/main/docs/release-signing.md).

## `/undo` and the Root's own restore never lose files

In v0.5.2, `/undo` removed your folder's entries before it copied the snapshot back, so a read-only folder (a Go
module cache, a vendored package) stopped it halfway with files gone. The Root's own system restore had the same
pattern, and an agent could make the Root's rollback fail by creating a read-only folder. Both are now all or nothing:
the snapshot is staged and checked first, entries are swapped by renames that never replace and never follow a link,
and a step that fails puts everything back. Plain `/undo` also never brings back a state an `/undo` replaced, and a
stuck probe file no longer breaks it.

## Statistics that hold their stated rates

Before changing anything, we measured v0.5.2 against a null: a goal whose changes did nothing ended `met` in 35–99 % of
simulated goals, and a reading said `better` on a no-effect change up to 42 % of the time. Now a reading's verdict is an
exact permutation test at 2.275 %, `met` needs p ≤ 5 % divided by the goal's rounds, and every change that goes live
during a goal spends a round. Simulated false `met` is 0–4.65 % per goal at rounds = 10
([STATS-053](https://github.com/nagisanzenin/INIT-Agent/blob/main/build/status/STATS-053.md)).

Guardrails on discrete cards (requests, cache reads, provider errors, corrections) now read 15 turns, because 5 turns of
a rare event hold too little evidence to see a fivefold rise. They catch at least what v0.5.2 caught in every measured
cell but one, with false rollbacks at most 2.2 %; the cost is a verdict about 10 owner turns later.

A level now means something you can check: at 95 % confidence, valid however often it is re-checked, the share of
exercised change groups (closed with at least 5 owner turns in their window) ending in a rollback attributed to direct
harm is below 25 % (L1), 20 % (L2), 10 % (L3) or 5 % (L4). Release builds still stop at L0.

## Signed releases

Each release's `SHA256SUMS` is signed with one ed25519 key. A fresh install checks the signature with `ssh-keygen`; an
upgrade from 0.5.3 on asks the installed Root, which pins the key at build time. Older releases and expired lists are
refused. A machine without `ssh-keygen -Y` (minimal Linux images, RHEL 8, Amazon Linux 2) is refused with the package to
install, or `--allow-unsigned` and its risk.

## The meter and the Root

- An unknown usage class is billed at the model's dearest price with a `price_drift` alert; `/usage` shows one price
  (the Root's, which over-counts DeepSeek's off-peak discount rather than under-count); a cut Anthropic stream is booked
  as an upper bound.
- **OpenAI gpt-6.1-sol was qualified live on v0.5.2** (2026-10-29); v0.5.3 changed how a cut request is booked and
  has not been re-qualified yet. Anthropic stays experimental.
- The Root re-hashes its own binary, profiles and charter at every admission (A0); a free-path promotion must name
  admitted content; a sealed audit can no longer move LKG backwards; genesis after an upgrade runs the release's kernel.
- Plain `/rollback` now works on the gated path. More credential stores, every other INIT install's homes and
  `~/.init-release` are denied to the agent.
- Every printed `init-agent` command carries its path; install.sh's PATH hint names your shell's file.

## Known limits

- With turns clustered in sessions, the GBAL bounds above are exceeded (2–9 % per reading, 12–24 % per goal in
  simulation). Fixing it needs the session in each observation (v0.6).
- The agent chooses when a change goes live, and so its baseline window: an open gaming vector, documented in ADR-013.
- In full access, INIT cannot protect commands you run in your own shell: the agent can edit your shell's startup
  files. Workspace mode (`init-agent --workspace`) confines it.
- A ROOT_HOME outside the usual places (for example under /tmp) is not found by the other-install deny list.
- Monte Carlo p-values (above 2^21 relabelings) act like a randomized test near the level (STATS-053).
- Release key 1 is a file key without a passphrase on the maintainer's Mac (docs/release-signing.md §8).
- Faster gates (L5) and the Root's property harnesses (L2) move to v0.5.4.
- From the user sessions (docs/user-sessions/v0.5.3-*.md): the uninstaller leaves `~/.local/share/init/<version>/`
  (the unpacked release) behind without saying so; `/help` does not list `/rollback`; the upgrade's "offering its new
  seed" line is unexplained; the gate track shows `deps □` while G0 already runs; `/details` shows the agent's preview
  of a call, not the whole call; the cache-read price is not shown anywhere; after a relaunch "this TUI N requests"
  also counts replayed requests; files `/undo` restores take the group of INIT's own folder.
- An agent that stacks changes faster than 5 owner turns gets owner guardrails that cannot decide; the Root now
  alerts when that happens (`goal_guard_unchecked`), but the baseline is not yet taken from an older tuple (ADR-013).
- `init-root audit verify` against a running Root can read the chain and its head between two appends and report
  INVALID; run it again, or with the Root stopped.
- The descriptor-relative `/undo` and R2 code paths for Linux were reviewed and built on the x86_64 runner; the
  restore itself was exercised on macOS.

## Corrections after the release

The day it shipped, a review of the published text (the release protocol's §7.5) found statements on this page and in
the docs that said more than was checked. They are corrected above and in the docs; the release itself is unchanged.

- **OpenAI gpt-6.1-sol** was called "tested live". It was qualified live on v0.5.2 (2026-10-29), and v0.5.3 changed
  how a cut request is booked, so it has not been re-qualified on this release. The app still shows it as
  live-tested until a re-qualify or v0.5.4.
- **The macOS checks** were presented as the shipped bundle's. The self-change through the gates, the source install
  and the upgrade from an evolved 0.5.2 ran on the candidate c045d65's bundle; the shipped bb5dc0e bundle differs from
  it only in `/undo`'s heartbeat wait.
- **A level's meaning** left out that it counts exercised change groups and rollbacks attributed to direct harm.
- **The `env -i` line** was said to matter once. Until v0.5.4 it matters for every upgrade, because 0.5.3's
  `init-agent upgrade` prefers a planted `INIT_ROOT_HOME` to its own home.
- **In the docs:** the Root's size is now the tag's (26,010 lines, of which the trusted computing base is 8,246 to
  12,298), not v0.5.0's 20,334. [Release signing](https://github.com/nagisanzenin/INIT-Agent/blob/main/docs/release-signing.md)
  names only the INIT Labs site as a place off GitHub to take the key's fingerprint from, says key 1 is pinned, and
  limits its claim against a variable planted in your shell to `INIT_DIST_URL`. The guide no longer says a mistyped
  `/word` is never billed. The warm-build receipt it cites (MERGE-T2CACHE) is now public.
