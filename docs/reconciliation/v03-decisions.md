# v0.3 reconciliation: main-session decisions

*Status: v0.3 + build sync 2026-10-20. These settle the cross-doc conflicts the five v0.3 doc agents reported. Each doc owner applies the items that touch its own files, then logs what it did in `docs/reconciliation/v03-<area>.md`.*

| # | Decision | Owner docs to change |
|---|---|---|
| D1 | **Sweep safety.** The instance sweep may kill a process only when all three conditions hold: (a) it is sandboxed; (b) it can read the instance mark; (c) it is denied the Root's canary or a sibling decoy file. This is supervise.md's fix. The v0.2 two-condition rule matched 31 of the owner's processes and killed them, including Docker Desktop. Tests of the sweep run only in a disposable environment. | root/root.md §3.5.4, kernel/supervise.md, kernel/sandbox.md, testing.md |
| D2 | **No hard-coding on self-written tasks.** Agent-authored tasks are admitted as **families** of at least 2 instances. At admission, the kernel (L1–L2) or the Root (L3+) seals a random half. The agent sees and develops only on the visible half. `capability_gain` needs a significant gain on the **sealed half** and non-inferiority on the Root's sealed set S. If all the evidence comes from agent tasks, `audit_required` still applies. | root/sealed-eval.md (admission owner), kernel/gate.md §3.9, evolution.md, testing.md |
| D3 | **Exclusion distance.** A task never judges descendants of its author within **K = 5 promotions**. Pre-registration is anchored to the Root lineage sequence number, not to a commit timestamp. | root/sealed-eval.md, kernel/gate.md, evolution.md |
| D4 | **No owner step is required anywhere.** `needs_owner` is removed. An inconclusive result gets one escalated re-run, and if it is still inconclusive the incumbent wins (`inconclusive_final`). `/accept`, `/bless` and `/reject` are optional signals that never gate anything. `/approve`, `/deny` and `/clear-safe` are removed; system safe mode clears automatically after 24 h (root.md). | kernel/gate.md, adr/006, root/root.md §3.15, kernel/supervise.md, evolution.md |
| D5 | **Sealed runs stay sealed.** Sealed audits and gate-of-gates runs never pass through the kernel proxy, or through any agent-zone process that can persist data. The Root launches an isolated reference body and evaluator on its own egress lane. Traces of S are never written anywhere the agent zone can read. | root/sealed-eval.md, root/egress.md, kernel/proxy.md |
| D6 | **Ceilings and demotion.** When a ceiling is lowered, soft budgets are clamped to it; nothing refuses to start. Only these count as an "attempt to exceed" that demotes: (a) an R3 action-class or policy violation; (b) a level-gated request refused by the Root; (c) a Root ceiling refusal at a moment when the kernel's soft-budget guard reported headroom (bypassing the guard). Ordinary ceiling hits, including the gap from peak-price estimates, are logged and do not demote. | root/egress.md, root/root.md (R7), kernel/proxy.md, kernel/config.md, evolution.md |
| D7 | **Lineage interface.** `lineage.append` gets a dedup key. The Root accepts every record kind the kernel and evolution docs use, including fleet kinds such as `task_suspended` and `fleet_campaign`. The Root writes `lineage/kernel.git`, which the agent zone can only read, and supplies the kernel source bundle for L3. | root/root.md, kernel/supervise.md, evolution.md |
| D8 | **Probe links.** root.md's V2 parameter check must allow the probe `LINK_*` parameters, or supervise.md must switch to an approach V2 accepts. The root.md owner decides together with supervise.md. | root/root.md, kernel/supervise.md |
| D9 | **`extra_read`.** The Root's tail rule Z2 denies only Root paths, so `extra_read` paths that the charter allows outside the Root directory work again. | root/root.md, kernel/sandbox.md |
| D10 | **crates.io access.** egress.md gets a built-in `crates` class, read-only to crates.io and static.crates.io, that `initctl vendor` uses. This is an L0 right with no approval. | root/egress.md, kernel/initctl.md |
| D11 | **Stop while paused.** The body accepts `stop` while paused at a handoff boundary. | body/loop.md, body/boot.md (edited by the kernel-supervise agent) |
| D12 | **Pass rates and drift.** Pass rates and the capability self-model live only in the kernel-written live copy `state/kernel/self.json`. The committed `self.json` leaves them out, and G1 compares only committed fields. | kernel/selfmap.md, awareness.md |
| D13 | **Charter template values, decided by the owner on 2026-10-20:** CH-1 `max_level = 4` (the agent still starts at L0 and climbs only on its measured record); CH-2 `/panic` demotes one level, while `stop` does not; CH-3 the off-machine mirror is a new private repo `nagisanzenin/INIT-Lineage`, pushed only by the Root with its own deploy key and created at M0. Money in the template: $5/day and a $25 total. Soft budgets stay in kernel config. | root/root.md, roadmap.md, awareness.md |
| D14 | **Noise floor of half a task, on the divergence guard only** (build: FIX2, FIX2 follow-up; WP8c finding 1). (1) The pool-versus-holdout divergence guard floors each split's δ at half a task: δ_min(set) = 0.5/n_set, δ_p' = max(δ_p, 0.5/n_pool), δ_h' = max(δ_h, 0.5/n_holdout); reject `pool_holdout_divergence` ⇔ D_pool − D_holdout > 2·√(δ_p'² + δ_h'²). A deterministic δ of 0 is not zero true noise: without the floor the gog's C1 was rejected on 4 holdout draws in 5. The split guards keep the measured δ. The NI margin stays m = max(2δ, 0.5/n), so G-21 is unchanged. A broader floor that also covered the split guards was measured and rejected, because it raised false accepts. The gate record adds `delta_min_permille` and, per split, `delta_floored_permille` next to the measured `delta_permille`. (2) On a holdout of fewer than 4 tasks, a score-gain accept (`better`, `capability_gain`, `repro_fixed`) becomes `inconclusive: underpowered:holdout`. `GAIN_MIN_HOLDOUT = 4` is a constant, not a config key; it applies after the accept rule and in the `audit_required` recompute; `cheaper`, `smaller` and `perf_gain` are unaffected. Without it, a 1-task holdout could never trip the floored guard, so a pool-only gain (the MS-5 signature) would pass as `better`. The gog's holdout must therefore hold at least 4 tasks. | kernel/gate.md §3.8.3, §3.9 and §8 (G-49), root/sealed-eval.md §3.3 |
